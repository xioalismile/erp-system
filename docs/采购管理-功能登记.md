**6 个单据一致的公共口径**（逐个读代码核实）：

- **列表入参**：`current / size / keyword / status / sortBy / sortOrder / customSearch`（6 个 Controller 签名一致）

- **数据权限**：`DataScopeResolver.applyTo(wrapper, "buyer_id")` → 全部数据 / 本部门数据 / 仅本人数据（仅本人 = `created_by=当前用户` OR `buyer_id=当前员工`）

- **列头排序**：`SortHelper.applyToWrapper(wrapper, sortBy, sortOrder, SORTABLE_COLUMNS)`，列名必须命中各 Service 的白名单（防注入）

- **自定义字段搜索**：`CustomFieldSearchHelper.apply(wrapper, "purchase_xxx", customSearch, idColumn)`（设置中心勾「可搜索」的字段才会出现在搜索栏）

## 二、变更记录

### 2026-09-16 采购合同列表：关键词 OR 分组缺括号 + 查询参数口径对齐通用组件

| 项    | 内容                                                                                                                                                                                      |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 问题   | 关键词命中「合同号」的行**绕过状态过滤、数据权限、自定义字段过滤**（按合同号搜索可越权看到他人合同）；同时列表页搜索框参数名与后端不匹配 → 搜索框输入等于没筛                                                                                                      |
| 根因   | ① `wrapper.like(..).or().like(..)` 平铺在最外层，MyBatis-Plus 不给 OR 分组补括号，SQL 中 `AND` 优先级高于 `OR` → 实为 `A OR (B AND C AND D)`；② 前端 `loadData()` 删掉 `keyword` 改发后端不认识的 `contractNo/supplierName` |
| 修复   | ① 关键词包成一组 `wrapper.and(w -> w.like("contract_no",kw).or().like("supplier_short_name",kw))`；② 前端参数口径改成与其它列表页一致（`keyword` + `customSearch` + 排序），清掉残留死映射 `dateRange→startDate/endDate`    |
| 改动文件 | `backend/.../purchase/service/impl/PurchaseContractServiceImpl.java`、`frontend/src/views/purchase/PurchaseContractList.vue`、新增单测 `PurchaseContractKeywordGroupTest.java`                |
| 证据   | 单测 4/4 PASS（退回旧写法 → 2 例变红）；真实接口 8/8 PASS（修复前同一脚本 B/C/D 三项红：状态被绕过、自定义字段被绕过、**仅本人角色越权看到他人已生效合同**）；浏览器点击级 9/9 PASS（搜索请求带 `keyword`；切「草稿」页签后该已生效合同消失；控制台 0 报错）                              |
