# 审批通用组件使用说明书（基准：销售订单的审批）

> 适用对象：所有带审批的单据（当前已接入 10 个身份：销售订单、采购订单、销售合同、客户授信、库存盘点单、库存调拨单、其他入库单、生产工单、生产组装单、生产拆卸单、生产入库单、生产领料单、生产退料单、生产补料单）
> 编写时间：2026-09-16　编写依据：**代码 + 真实运行结果**（真实提交/审批/回写 + 数据库前后对比，非文档推测）
> 用途：① 新单据接入时的对接契约；② 已接入单据的排查清单（见第 6 节自检表）

***

## 1. 功能概述

一次完整审批 = 「开关判断 → 提交建任务 → 按流程走节点 → 审批结果回写单据」四段，全部由通用件提供，单据侧只做三件事：

| 通用件   | 业务职责                                   |
| ----- | -------------------------------------- |
| 开关网关  | 判定该单据"要不要走审批"（全局总开关 + 单据级开关，默认**免审批**） |
| 审批引擎  | 提交时创建审批任务、按流程选节点与审批人、推进/终结流程、发通知       |
| 回写回调  | 审批结果落回单据（通过→执行该单据的"生效"动作；驳回→退回草稿）      |
| 通用接入件 | 给"没有继承通用单据基类"的手写单据服务复用上面三件（口径与基类完全同源）  |

单据侧只需要：①声明自己的身份编码；②在"提交"里按开关分流；③实现回写回调。**前端不用改任何审批逻辑**（按钮通用件 + 审批流转时间线会自动适配）。

***

## 2. 入参

### 2.1 后端：提交进入审批（单据服务 → 通用接入件）

| 参数名          | 业务含义       | 类型 | 必填 | 取值/说明                                                                   |
| ------------ | ---------- | -- | -- | ----------------------------------------------------------------------- |
| `billType`   | 单据身份编码     | 文本 | 是  | 必须与**设置中心审批开关的登记编码**一致（销售订单 = `SALE_ORDER`）；一个服务支持多个身份时用第 5.9 条的集合写法    |
| `billId`     | 单据主键       | 整数 | 是  | 该单据表的主键（销售订单 = `orderId`），审批任务按它回查单据                                    |
| `billNo`     | 单据编号       | 文本 | 是  | 审批待办与通知上展示的单号                                                           |
| `submitter`  | 发起人（登录用户名） | 文本 | 否  | 取不到时引擎按"系统"处理；推荐用通用接入件的"取当前登录人"方法                                       |
| `billEntity` | 单据实体       | 对象 | 是  | 用于生成"条件路由数据快照"（表头字段 camelCase + snake\_case 双写 + 该单据的自定义字段值），供流程条件表达式匹配 |

### 2.2 后端：单据自身的前置校验（提交前必须自己做）

| 校验      | 说明（销售订单口径）                      |
| ------- | ------------------------------- |
| 只有草稿可提交 | 非草稿直接报错，不允许把"已生效/已关闭"重新提交       |
| 不允许重复提交 | 已有**在途审批任务**时不得再次提交（引擎会拦截重复建任务） |
| 业务必填校验  | 如销售订单的客户/明细/金额等，属单据自身职责，不属通用件   |

### 2.3 前端：调用审批相关通用件需要传什么

| 通用件           | 入参                                       | 说明                                            |
| ------------- | ---------------------------------------- | --------------------------------------------- |
| 顶部按钮栏（单据操作按钮） | 单据身份编码、单据状态、结案标志、是否新建、**本页已具备执行能力的动作清单** | 按"状态允许 + 开关允许 + 本页确有该能力"三重判断显隐；缺能力直接不渲染按钮     |
| 单据操作逻辑（组合式函数） | 表单对象、取主键方法、各动作对应的接口、成功后回调                | 返回"审核/驳回/重置草稿/结案/反结案/作废/反作废/删除"的处理函数 + 已接线动作清单 |
| 提交确认弹窗        | 单据身份编码、单据中文名、单号                          | 按开关给出不同文案（走审批 / 直接生效）                         |
| 审批流转时间线       | 单据身份编码、单据主键、当前状态                         | 按"身份 + 主键"查该单据的审批任务与日志                        |
| 审批开关读取        | 单据身份编码                                   | 带缓存；接口异常时按"单据级=关、全局=开"兜底                      |

## 3. 出参（返回什么）

### 3.1 提交阶段

| 场景                           | 返回/结果                                                                        |
| ---------------------------- | ---------------------------------------------------------------------------- |
| 开关**关**（免审批）                 | 通用接入件返回"未走审批"，单据由调用方落「已生效」并执行生效动作（**审核人留空，不写系统占位**），**不产生审批任务**                 |
| 开关**开**                      | 通用接入件返回"已走审批"，单据落「待审核/待审核」，并返回一个**审批任务**（含任务号、流程号、节点号、单据身份/主键/单号、审批人、状态=待处理） |
| 开关**开但无可用流程 / 审批人无法解析到启用账号** | 抛出业务异常，**整个提交事务回滚**（单据留在草稿），前端看到明确提示                                         |
| 重复提交                         | 已有在途任务时拒绝再次提交                                                                |

### 3.2 审批阶段

| 动作       | 返回/结果                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------- |
| 审批通过     | 任务状态→已通过 + 完成时间；**回写单据**：执行该单据的"生效"动作（销售订单=审核：状态→已生效、approval\_status→已生效、写审核人与时间、释放库存占用/信用等业务影响） |
| 审批驳回     | 任务状态→已驳回 + 完成时间；**回写单据**：状态→草稿、approval\_status→驳回（业务影响不产生/回退），可修改后重新提交                           |
| 查询我的待办   | 返回任务列表（只含状态=待处理，且当前审批人或候选人包含本人）                                                                   |
| 查询单据审批流转 | 返回该单据的提交/通过/驳回日志（按单据身份 + 主键）                                                                      |

### 3.3 单据侧的落库结果（销售订单为例）

| 字段                            | 含义         | 提交后 | 通过后      | 驳回后 |
| ----------------------------- | ---------- | --- | -------- | --- |
| `status`                      | 单据状态       | 待审核 | 已生效      | 草稿  |
| `approval_status`             | 审批状态       | 待审核 | 已生效      | 驳回  |
| `approved_by` / `approved_at` | 审核人 / 审核时间 | 空   | 审批人 / 时间 | 清空  |
| `close_status`                | 结案标志       | 0   | 0        | 0   |

## 4. 依赖

### 4.1 后端通用件（接入方只需调用，不要复制实现）

| 依赖                           | 用途                                        |
| ---------------------------- | ----------------------------------------- |
| 开关网关（`ApprovalGateHelper`）   | 判定"要不要走审批"：全局总开关 + 单据级开关，**默认免审批**        |
| 审批引擎                         | 建任务 / 选流程 / 校验审批人 / 推进节点 / 终结 / 通知        |
| 流程配置服务                       | 按"单据身份 + 数据快照"选启用中的流程（含条件路由、优先级）          |
| 回写回调接口                       | 引擎按"单据身份"找到单据服务并回写结果（支持一个服务多个身份）          |
| 通用接入件（`BillApprovalAdapter`） | 提交接入 + 条件路由数据快照 + 取当前登录人；口径与通用单据基类同源      |
| 通用单据基类                       | 已继承它的单据（销售订单、采购订单）自带提交/回写；未继承的用手写 + 通用接入件 |

### 4.2 数据库（缺任一都会断链）

| 表 / 配置                                   | 关键字段                                                                                                                    | 说明                                 |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| `sys_config`                             | `approval.enabled`（全局总开关，默认开）、`approval.bill.<身份>.enabled`（单据级开关，**默认关**）                                               | 单据级键不存在时按"关"处理                     |
| `approval_flow`                          | `bill_type`、`enabled`、`priority`、`condition_expr`                                                                       | 该单据**必须有一条启用中的流程**，否则提交报错回滚        |
| `approval_node`                          | `flow_id`、`node_order`、节点类型/审批方式                                                                                        | 流程节点                               |
| `approval_node_approver`                 | `node_id`、`user_id`、`approver_name`                                                                                     | **审批人必须能解析到启用账号**，否则提交报错回滚         |
| `approval_task`                          | `bill_type`、`bill_id`、`bill_no`、`task_status`、`current_approver`、`assignee_ids`、`submit_by`、`submit_time`、`finish_time` | 审批任务；待办查询按 `task_status='pending'` |
| `approval_log` / `approval_notification` | `bill_type`、`bill_id`、动作、操作人、时间                                                                                         | 审批留痕与通知                            |
| 单据表                                      | `status`、`approval_status`、`approved_by`、`approved_at`、`close_status`                                                   | 回写目标字段（列必须真实存在）                    |

### 4.3 单据身份必须登记的 5 处（少一处就会出现"看不到/点不开/不生效"）

| # | 登记点                            | 不登记的后果                      |
| - | ------------------------------ | --------------------------- |
| 1 | 设置中心审批开关清单（**后端数组 + 前端树两处**）   | 用户看不到开关，无法启用                |
| 2 | `sys_config` 开关种子（幂等 SQL）      | 新环境部署后没有这个开关                |
| 3 | 铃铛通知名称表 + 工作台待办名称表（**两份独立的表**） | 通知/待办显示英文编码，或**点不开**        |
| 4 | 引擎回写回调（实现回调接口）                 | 审批通过/驳回**静默不回写**，单据永久卡"待审核" |
| 5 | 部署清单 `deploy-kit-manifest.txt` | 打包发版时 SQL 不执行，新环境缺流程/开关     |

> 另：若该单据要用 AI 小助手执行流程动作，还需登记 AI 动作注册表（并在权限解析表登记其菜单权限码）；若要用打印/导出/关联台账，还需在对应登记表登记——**未登记时 AI/打印/导出会直接报"不支持该单据类型"**。

### 4.4 前端依赖

| 依赖                | 用途                 |
| ----------------- | ------------------ |
| 顶部按钮栏 + 单据操作组合式函数 | 按钮显隐与动作调用（能力缺失不渲染） |
| 审批开关读取工具（带缓存）     | 按钮与提交提示按开关联动       |
| 提交确认弹窗工具          | 按开关给出"走审批/直接生效"文案  |
| 审批流转时间线组件         | 展示该单据的审批进度         |

## 5. 注意事项（边界条件）

1. **开关默认关**：单据级开关默认"免审批"，接入后**用户不改配置，行为与升级前完全一致**（提交即生效）。这是硬要求。
2. **无流程 / 审批人无效 → 提交直接报错回滚**：单据留在草稿，绝不产生"状态待审核、但没有任何人有待办"的卡死单据。
3. **草稿才能提交**；**在途任务存在时不得重复提交**（引擎拦截），避免一人多任务、重复生效。
4. **"通过"必须映射到该单据真正的生效动作**：

   - 销售订单/采购订单/销售合同 → 审核（状态=已生效）

   - 生产工单 → **下达**（该单据没有独立"审核"动作，其生效动作是下达，状态=已下达）

   - 生产入库单/领料单/退料单/补料单/盘点单/调拨单/其他入库单/组装单/拆卸单 → 各自既有的审核逻辑
     接入时必须逐单据确认这个映射，**不要一律套"已生效"**。
5. **驳回 = 回草稿 + approval\_status=驳回**，并回退已产生的业务影响（如库存占用/信用）。
6. **有待办时禁止绕过引擎直点审核**：单据页面的"审核"按钮在有待办时应被拦截并提示"请到审批中心处理"，否则会出现"任务未终结但单据已生效"。
7. **反向操作（重置草稿 / 撤销 / 作废 / 取消）应终结在途待办**：当前实现**未做**——会在待办里留下没人处理的"僵尸待办"（已接入的 10 个身份均有此风险，属已知待办项）。
8. **提交人取值**：单据的提交接口若没有"提交人"参数，用通用接入件取当前登录人；取不到时引擎按"系统"记，审计上会丢人。
9. **一表多身份**（如生产领料单/退料单/补料单共用一张表）：用回调接口的"支持身份集合"能力，提交时按记录自身的单据类型选择身份与开关；回写按身份路由回同一服务。**导入导出/关联台账仍按主身份登记**（系统校验禁止"一张表两个登记实体"）。
10. **条件路由数据快照口径必须与通用件一致**（表头字段 camelCase + snake\_case 双写 + 自定义字段值），否则流程条件匹配不上、选不到期望的流程。
11. **审批人与显示名**：节点审批人写成**登录名**更稳（引擎会解析显示名，姓名/员工档案变动会导致"您不是当前节点的指定审批人"）。
12. **上线前必须验证"开关关时行为不变"**（免审批回归），以及"开关开时提交→待办→通过→库存/状态正确"整条链路。

## 6. 自检表（新单据接入 / 已接入单据排查）

| #  | 检查项                            | 判定标准                                |
| -- | ------------------------------ | ----------------------------------- |
| 1  | 身份编码是否与设置中心开关登记一致              | 前后端两份清单都有该编码与正确的中文名                 |
| 2  | `sys_config` 是否有该身份的开关（幂等 SQL） | 库中存在，默认值为 false（= 旧行为）              |
| 3  | 是否实现回写回调并映射到正确的生效动作            | 通过→该单据真正的生效动作；驳回→回写草稿+驳回            |
| 4  | 提交是否按开关分流（开=建任务落待审核；关=提交即生效）   | 两条分支都实测过                            |
| 5  | 是否有一条启用中的审批流程 + 审批人能解析到启用账号    | 提交能建出任务，任务审批人正确                     |
| 6  | 是否拦截"有待办绕过引擎直审"                | 待办存在时直点审核被拦                         |
| 7  | 通知名称表 + 工作台待办名称表是否都登记          | 铃铛与工作台显示中文名、点击能打开单据                 |
| 8  | 前端页面身份是否传对（按钮栏 + 流转时间线 + 提交确认） | 三处身份一致，按钮显隐随开关变化                    |
| 9  | 免审批回归                          | 开关关时提交即生效、不产生任务、行为与升级前一致            |
| 10 | 部署清单是否登记 SQL                   | 打包发版时能带上开关与流程种子                     |
| 11 | 反向操作是否终结在途待办                   | 未做则登记为已知风险（当前全部未做）                  |
| 12 | 结案/反结案字段口径                     | 结案写 `close_status=1`、反结案归 0（与全系统一致） |
