# 字段权限统一方案（系统性改造说明）

> 建立日期：2026-11-27
> 背景：此前字段权限是"按接口路径手写 + 只在 JSON 响应里过滤"，导致列表生效、导出泄露、这张单生效下一张不生效。本次改为**按单据实体自动推导、在统一出口执行**，不再逐接口/逐导出方法打补丁。
> 关联：[功能体检-权限运行体检.md](功能体检-权限运行体检.md)、[单据标准与能力登记.md](单据标准与能力登记.md)

---

## 1. 设计原则

1. **单一事实源**：页面键（page_key）不再手写路径表，而是从数据本身推导：
   - 列表/详情接口 → 返回实体的 `@TableName`（如 SaleOrder → `sale_order`）；
   - 明细报表 → 报表配置的主表（`BillDetailReportConfig.mainTable`，启动扫描自动）；
   - 打印 → 单据类型在来源去向登记表里的主表（`BillLinkRegistry.tableOf`）；
   - 导出 → 导出实体的 `@TableName`（ExportController 统一标记）。
2. **单一策略服务**：`FieldVisiblePermissionService` 是"当前用户在某页面不可见哪些字段"的唯一出口，响应过滤、导出、打印共用同一份解析与缓存（60 秒），管理员/无上下文统一放行。
3. **每个输出通道只有一个卡点**，不在业务方法里各写一遍：
   - JSON 响应 → `FieldPermissionResponseAdvice`
   - Excel 数据导出 → `ExcelServiceImpl.writePositionalSheet`（所有数据导出最终都走它）
   - 明细报表导出 → `AbstractBillDetailReportController.doExport`
   - 打印取数 → `PrintDataFetcherService.fetchBillData`
   - 前端列显隐 → `useColumnSetting`（页面键按登记表自动取）
   - AI 小助手 → 通用查询在 `AiCrudAgentService.query`、固定报表在 `ReportQueryTool`、聚合排行在 `ReportAggregateQueryTool`、数据源字段清单在 `CustomReportServiceImpl.describeDataSource`
   - 自定义报表 → 设计器字段清单 / 运行结果 / 导出三处共用 `CustomReportServiceImpl` 里同一份不可见集合
4. **AI 线程显式传用户**：小助手工具跑在线程池，没有请求上下文；`FieldVisiblePermissionService.hiddenKeysFor(userId, admin, pageKey)` 按用户解析，所有 AI 查询工具都把 `AiDataScope` 往下传（`Query*Tool` 已全部补上带 scope 的执行入口）。
5. **启动自检点名**：`BillPermissionCoverageReporter` 启动时检查所有导出实体能否由 `@TableName` 得出页面键，得不出直接 WARN 点名；不能再靠人记。

## 2. 覆盖矩阵

| 通道 | 入口 | 统一卡点 | 状态 |
|---|---|---|---|
| 列表 / 详情 JSON | 各单据 Controller | 响应过滤：先按返回实体 `@TableName`，Map/视图回退报表/路径登记 | ✅ |
| 明细报表 JSON | 45 个报表控制器 | 响应过滤：报表配置主表自动对应（含"全明细"合并报表） | ✅ |
| Excel 按可见列导出 | `/api/export/data/{entity}/visible` | 导出控制器标记页面键 → 统一写盘剔列 | ✅ |
| Excel 勾选导出 | `/data/{entity}/selected` | 同上（内部走 exportData） | ✅ |
| Excel 全量导出 | `/data/{entity}` | 同上 | ✅ |
| Excel 自定义列导出 | `/data/{entity}/custom` | 同上 | ✅ |
| 库存现存量 / 价格策略导出 | 专用导出 | 同样经过 `writePositionalSheet` | ✅ |
| 明细报表导出 | `/api/report/.../export` | 报表控制器导出前按主表剔 key 与值 | ✅ |
| 打印取数 | 打印模板渲染 / 打印接口 | `fetchBillData` 统一剔除表头与明细行不可见字段 | ✅（已按代码验证；默认模板未展示联系电话，值级端到端待有该字段的模板） |
| 前端列显隐（汇总+明细） | 所有列表页 | `useColumnSetting` 按 `billPagePermKeys` 自动取键 | ✅ |
| AI 通用查询（query_* / generic_query） | 小助手工具 | `AiCrudAgentService.query`：按实体 `@TableName` 剔结果与 labels | ✅（实测） |
| AI 固定报表 | `report_query` | `ReportQueryTool`：按报表主表剔 records / labels / stats / totals，统计文案同步不报 | ✅（实测） |
| AI 聚合排行 | `report_aggregate_query` | `ReportAggregateQueryTool`：分组/指标/日期字段不可见直接拒绝 | ✅ |
| AI 数据源字段清单 | `report_list_datasources` | `CustomReportServiceImpl.describeDataSource` 同一份规则 | ✅ |
| 自定义报表 设计器 | `/api/report/custom/datasources/{key}` | 字段清单剔不可见字段（主表 + 各关联表并集） | ✅（实测） |
| 自定义报表 运行 | `/api/report/custom/{id}/run` | 行数据、列定义、合计行一起剔；隐藏字段不能当筛选条件 | ✅（实测） |
| 自定义报表 导出 | `/api/report/custom/{id}/export` | 表头与数据同时剔 | ✅（实测） |
| 启动自检 | 应用启动 | 导出实体 `@TableName` 覆盖率日志 | ✅（69 个实体全部可推导） |

## 3. 新增单据时自动获得什么

- 只要实体标了 `@TableName`、页面在 `billPagePermKeys` 登记（或直接由静态体检表生成），**列表、明细、导出、打印自动套字段权限**，不需要再登记接口路径。
- 新增明细报表：放进 `report/controller` 并继承报表基类，**自动进入报表目录和字段权限映射**。
- 新增导出入口：只要最终走 `writePositionalSheet`（数据导出统一写盘方法），**自动剔列**。如果新写一条绕过它的导出通道，启动自检不会发现——这属于新增导出方式时需要遵守的唯一约定（见第 5 节）。

## 4. 本次实测（同一临时受限账号，测后已删）

第一轮（列表 / 明细报表 / 导出 / 打印 / 前端列显隐 / 数据权限）：

- 列表字段权限：销售订单、销售出库、采购订单、采购申请、采购入库、其他入库全部按配置剔除；
- 明细报表字段权限：销售订单、采购申请均剔除；
- 导出：按可见列、全量、明细报表导出三种方式，隐藏的联系电话/价税合计在表头和值里都不存在；管理员不受影响；
- 打印：受限账号与管理员都未在默认模板里展示该字段（值级结论待有该字段的模板再验）；
- 前端：受限用户打开销售发票汇总页，"开票价税合计"列被自动隐藏（该页未显式传权限键，验证了自动取键）；
- 数据权限：抽样 9 个单据 + 2 个报表，本人数据范围均返回 0 行（过滤生效）。

第二轮（AI 小助手 / 自定义报表，2026-11-27 补）：

| 通道 | 实测结果 |
|---|---|
| AI 通用查询 | 受限账号问"查询销售订单，列出订单号和客户联系电话"：销售订单工具返回 15 个字段、无联系电话/联系人；客户档案工具返回的 32+1 条记录也没有联系电话/联系人；整段回答里没有任何电话号码 |
| AI 固定报表 | 问"用销售订单明细报表查一下，带上联系电话和价税合计"：返回 76 行，记录里没有联系电话/联系人/净额；统计只剩"单据 56 张、数量合计 678.00"，价税合计整项不出现 |
| AI 数据源字段清单 | 客户数据源返回 72 个字段，不含联系电话/联系人；销售订单数据源不含净额 |
| 自定义报表·设计器 | 销售订单数据源返回 69 个字段，不含联系电话/联系人/净额（含各关联表） |
| 自定义报表·运行 | 用接口直接建一张含 contactPhone/contactPerson/netAmount 的报表（绕过设计器）：运行只返回 orderNo 一列、56 行；把隐藏字段当筛选条件直接被拒（提示"字段在当前账号的字段权限中不可见"） |
| 自定义报表·导出 | 导出文件只有"订单号"一列、57 行（含表头），没有联系电话表头，也没有任何电话号码 |

顺带修复（验证过程中发现，不修则 AI 报表通道实际不可用）：

- **报表菜单路由**：`BillDetailReportCatalog` 原来用接口路径拼菜单路由（`/sale/report/order-detail`），与菜单表真实路由（`/sale/report/sale-order-detail`）对不上，非管理员查固定报表永远"无权限"。改为按报表中文名 = 菜单名从 `sys_menu` 取真实路由，取不到才回退推导。
- **工具预筛**：`report_query` / `report_aggregate_query` 未登记为常驻工具，用户话术带任何实体词就会被关键词预筛整体丢弃（模型回"没有这个工具"）。已加入 `ALWAYS_TOOLS`（是否真正暴露仍由 ToolRegistry 的只读白名单与执行期菜单权限决定）。

> 临时角色、菜单权限、字段权限、账号、该账号创建的报表与 AI 对话/用量记录已全部删除（逐表核验为 0）。

## 5. 仍未覆盖 / 唯一需要遵守的约定

| 项 | 说明 |
|---|---|
| 导入模板列 | 模板只暴露字段结构，不含业务数据；未剔除（保持用户可下载完整模板） |
| 新增导出通道 | 必须走 `writePositionalSheet`（或显式调用 `FieldPermissionOutputFilter`）；这是唯一靠约定的点，后续可加静态扫描测试兜底 |
| AI 对话历史 | 字段权限生效前已经问出来的历史答案不会回溯清理（`ai_chat_history` 按用户永久保存）；需要时按会话删除 |
| 自定义报表的历史配置 | 旧报表配置里如果已经包含后来被设为不可见的字段，运行/导出会自动剔除，但配置本身仍在（重新保存时会再次校验） |

- 导出控制器标记：`export/controller/ExportController.java`
