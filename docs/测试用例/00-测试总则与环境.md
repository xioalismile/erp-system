# ERP 测试用例总则与环境

> 用途：手工验收 + 自动化回归共用。用例按模块分文件，编号全局唯一，预期结果必须可判定对错。

## 零、口径权威顺序（写用例前必读）

1. `.trae/rules/11-单据状态机标准.md` —— 状态、动作、按钮显隐、免审批审核人留空等**唯一事实来源**。
2. `.trae/rules/10-防复发坑记录.md` —— 已知坑，相关章节的结论直接写进用例预期。
3. `.trae/rules/06-强制测试.md`、`01-沟通与前置流程.md` —— 测试与交付流程要求。
4. 代码实现 —— 只用来确认"实现有没有偏离标准"。

**判定规则**：代码与标准不一致 → **记缺陷**（附文件与行号），不写成"产品待确认项"。
可复跑的官方核查工具（只读）：
- `node deploy/local-run/verify-bill-state-machine-adoption.cjs` —— 逐单静态核查（是否继承基类、是否自写状态迁移）。最近一次：42 张已接入 / 0 张未接入 / 0 处自写迁移。
- `deploy/local-run/verify-all-bill-state-machine.cjs` —— 跨模块接口级生命周期验收。
- `npm run check:relations` / `npm run check:dropdown` —— 前端推单登记与下拉字段核查。

## 四、编号与优先级

编号 = 模块前缀 + 三位序号：`TY` 通用、`JC` 基础资料、`SZ` 系统设置、`KC` 库存、`WZ` 委外、`CG` 采购、`XS` 销售、`SC` 生产、`CW` 财务、`BB` 报表。

| 优先级 | 含义 | 不通过的后果 |
|---|---|---|
| P0 | 阻塞主流程：单据建不出、审核不了、库存/金额算错 | 该模块不可交付 |
| P1 | 影响体验或数据不准：按钮缺失、提示不清、边界值异常 | 记缺陷，限期修 |
| P2 | 边缘场景：超长、并发、极端数值 | 记缺陷，可不阻塞 |

## 五、用例格式

| 编号 | 模块 | 优先级 | 前置条件 | 步骤 | 预期结果 |
|---|---|---|---|---|---|

规则：
1. 一条用例只验一个点；"新增成功并能在列表看到"和"编码重复被拦"是两条。
2. 预期结果写**可判定**的：具体数值、具体提示文字、具体状态名，不写"正常"。
3. 每条单据闭环固定查八项：单号、状态、来源单关联、明细行数与数值、库存变化、金额、列表检索、反审回滚。

## 六、每条单据闭环的通用检查点（TY-001 ~ TY-008）

| 编号 | 检查点 | 预期 |
|---|---|---|
| TY-001 | 新建保存 | 单号自动生成且**保存后再保存/提交，单号不变**；地址栏出现单据 id；刷新仍是同一张单 |
| TY-002 | 列表回读 | 新单出现在列表首行，状态非空，单号可点进详情 |
| TY-003 | 详情回显 | 表头字段、明细行数、每行数量/单价/金额与填写值逐字一致 |
| TY-004 | 来源单关联 | 选单/下推生成的单据，来源单号、来源行号正确；来源单"去向单据"页签能看到本单 |
| TY-005 | 库存影响 | 审核后即时库存数量、移动平均成本按规则变化；反审后**按原成本**回到审核前 |
| TY-006 | 金额影响 | 行小计之和 = 合计；税额、价税合计口径与表头计税方式一致 |
| TY-007 | 状态机 | 只出现该状态允许的动作；不允许的动作要么不显示，要么点击后给出明确原因 |
| TY-008 | 清理 | 作废/删除后库存与成本回滚；被下游引用的单据删除被拦并提示引用方 |

## 七、缺陷提交

每条缺陷附：用例编号、环境与租户、操作路径、期望 vs 实际、截图、接口返回（F12 Network 对应请求）、影响范围（哪几张单据/哪个数值）。

## 九、建议执行顺序

1. 基础资料（01）→ 前置数据必须先成立，其它模块都依赖它。
2. 系统设置（02）→ 开关两态会改变后面所有模块的表现，先确认口径。
3. 库存（03）→ 库存是所有单据的落点，先建立"数对"基线。
4. 采购（04）→ 销售（05）→ 生产（06）→ 委外（07）→ 财务（08）→ CRM（09）→ 打样（10）→ 通用（11）。
5. 每修一个缺陷，把对应用例编号补进 `03-e2e-loop` 或新增断言，形成回归。
