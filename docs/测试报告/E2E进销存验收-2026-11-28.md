## 四、测试发现的界面/可用量缺陷

账面数量、金额、成本全部对得上；以下问题不影响账面金额，但影响用户看到的数据和后续可用量判断。

### 缺陷 1（高）：即时库存“订单占用/预计可用量”算错

- 现象：即时库存页 `E2E-主仓` 显示库存 40、订单占用 **80**、预计可用量 **-40**；订单页物料行也显示预计可用量 -40。
- 实际：订单 80 件，已出库 70、已退货 15，按系统勾稽应为占用 25 件（80 − 70 + 15），预计可用 40 − 25 = **15**。
- 原因：`VirtualStockServiceImpl` 用 `quantity - delivered_quantity` 计算占用，但全系统没有回写 `delivered_quantity`，真实回写字段是 `turned_output_quantity / turned_return_quantity`。订单 209 的 `delivered_quantity` 为 0，`turned_output_quantity` 为 70。
- 影响：部分发货后订单占用虚高，预计可用量偏小甚至为负，可能影响接单、出库可用量判断。
- 证据：`即时库存-订单占用显示.png`；订单 209 的 `turned_output_quantity=70, turned_return_quantity=15, delivered_quantity=0`。

### 缺陷 2（中）：销售订单列表“开票情况/退货情况”显示 0

- 现象：销售订单列表（明细视图）显示 `已开 0.00 / 80.00`、`已退 0.00 / 80.00`；实际已开票 70、已退货 15。
- 原因：明细报表 `RowWritebackSql.saleInvoiceQty/saleReturnQty` 用发票/退货明细的 `source_item_id`（=出库明细 ID）和 `source_bill_no`（=出库单号）去匹配订单明细 ID / 订单号；正常“订单→出库→发票/退货”链路是两跳，匹配不到，恒为 0。
- 影响：列表页看不到真实开票/退货进度；数据库和订单勾稽字段是正确的。
- 证据：`订单列表-勾稽显示.png`。

### 缺陷 3（中，待确认口径）：订单列表“收款情况”显示 0

- 现象：收款单 1100 已确认并核销销售发票，但销售订单列表“收款情况”仍显示已收 0。
- 原因：收款核销落到销售发票来源（`bill_writeoff_detail`），未回写订单表头/明细的已收金额；订单页收款口径只汇总订单/应收来源。
- 影响：从订单列表看客户已付款，但订单显示未收款。是否属于设计口径需要确认。

### 观察项：下推销售出库单自动生效，仓库为空先扣默认仓

- 现象：销售订单下推出库单后单据已生效；明细没有仓库，系统按表头默认仓（主仓库）先扣 80，随后为补明细仓库必须反审/改单/重审，产生 `SALE_OUT 80` 与 `SALE_OUT_REVERSE 80` 冲回流水，并留下主仓库 0 库存行。
- 影响：最终库存正确（40 件），但流水和零库存行有测试痕迹；若系统关闭负库存，下推可能直接失败。
- 建议：下推时先按明细行仓库/表头仓库完整落库再自动生效，或自动生效前强制补仓库。

## 七、修复复验（2026-11-28 晚）

三个界面/可用量缺陷已修复并复验：

| 缺陷 | 修复 | 复验结果 |
|---|---|---|
| 1. 订单占用/预计可用量算错 | `VirtualStockServiceImpl` 改用 `turned_output_quantity - turned_return_quantity`（净出库），不再用死列 `delivered_quantity` | 即时库存 `E2E-主仓` 订单占用 **25**、预计可用 **15** |
| 2. 订单列表已开/已退显示 0 | `RowWritebackSql` 新增订单行专用两跳聚合：发票/退货明细 → 出库明细 → 订单明细；`SaleBillDetailReportConfigs` 切换到新取数 | 列表显示 `已开 70.00 / 80.00`、`已退 15.00 / 80.00` |
| 3. 订单列表收款情况为 0 | 收款核销销售发票/出库单时，按“发票→出库明细→订单明细”拆分回写订单表头/明细已收；作废/反作废对称回减/重写 | 订单表头/明细已收 **1100**，列表显示 `已收 1100.00` |
