# 单据与页面登记（标准登记表）

> 建立日期：2026-11-27（2026-11-27 按"系统说法"重写：只分四栏，不再使用难懂的专业词）
> 用途：新增任何单据/页面，先填四栏；系统按四栏选通用组件、套默认功能、接必需登记点。现有页面按同一张表补齐。
> 口径：只登记已实查项；未核实标注「未核实」。

---

## 0. 一句话

**新增东西时只填四栏：这是什么东西、有没有明细、页面怎么用、要开哪些功能。**
第 2、3 栏决定用哪个通用组件；第 1 栏决定默认开哪些功能；第 4 栏决定接哪些登记点、怎么验。

---

## 1. 登记表四栏

| 栏位 | 怎么填 | 起什么作用 |
|---|---|---|
| **1. 这是什么东西** | 单据 / 基础资料 / 台账 / 报表 / 看板 / 待办 / 设置 / 向导 | 决定默认开哪些功能、生命周期、权限口径 |
| **2. 有没有明细** | 没有 / 一张单带明细 / 两张明细 / 只有汇总结果 / 参数表 | 决定用不用明细表格、明细模式还是全明细 |
| **3. 页面怎么用** | 列表+编辑 / 只读列表 / 报表 / 看板 / 待办 / 设置 / 向导 | **决定用哪个通用组件** |
| **4. 要开哪些功能** | 从功能清单里勾（见第 3 节） | 决定接哪些登记点，勾了就必须接上并验收 |

### 第 1 栏的取值（系统里的说法）

| 类型 | 特征 | 系统例子 |
|---|---|---|
| 单据 | 有状态：草稿/待审核/已生效/已取消/已作废；可提交、审批、作废 | 销售订单、采购入库、生产工单、收款单 |
| 基础资料 | 客户/物料/员工等；有启用/停用，不做审批；不做物理删除 | 客户档案、物料档案、币种、仓库 |
| 台账 | 只读，系统自动产生，不提供新增/编辑/审批 | 即时库存、库存流水、操作日志 |
| 报表 | 只读，按条件统计或列明细 | 各单据明细报表、对账单、分析报表 |
| 看板 | 卡片、图表、可下钻 | 经营看板、销售看板、车间排程 |
| 待办 | 待处理队列，有处理动作 | 报工待确认、未关联数据、消息中心 |
| 设置 | 配置系统行为 | 设置中心、字段权限、打印模板、编码规则 |
| 向导 | 分步操作 | MRP 运算 |

### 第 2 栏的取值

| 有没有明细 | 含义 | 例子 |
|---|---|---|
| 没有 | 一行就是一张单，或纯资料 | 工序汇报单（已并入工单）；客户档案 |
| 一张单带明细 | 表头 + 一张明细表 | 销售订单、采购订单、生产工单 |
| 两张明细 | 表头 + 两张明细表 | 收款单（核销明细+收款明细）、付款单、生产工单（成品+原料）、组装/拆卸、费用分摊 |
| 只有汇总结果 | 没有可编辑明细，只有统计结果 | 报表、看板 |
| 参数表 | 配置项，不是业务明细 | 系统参数、编码规则 |

### 第 3 栏的取值与对应组件

| 页面怎么用 | 用的通用组件 | 系统里的例子 |
|---|---|---|
| 列表+编辑，带明细 | 标准列表页 + 标准编辑页 + 明细表格 | 销售订单、采购入库、生产工单 |
| 列表+编辑，不带明细 | 标准列表页（基础资料表格）+ 标准编辑页 | 客户、物料、员工、币种 |
| 列表+编辑，两张明细 | 同上 + 全明细（列设置自动出两边字段） | 收款单、付款单、生产工单、组装/拆卸、费用分摊 |
| 只读列表 | 标准列表页（只读，不给新增/编辑） | 库存流水、即时库存、操作日志 |
| 报表 | 明细报表页 / 报表中心 | 各单据明细报表、对账单、分析报表 |
| 看板 | 看板组件 | 经营看板、销售看板、车间排程 |
| 待办 | 只读列表 + 批量处理条 | 报工待确认、未关联数据、消息中心 |
| 设置 | 设置中心组件 | 用户权限、字段权限、打印模板、编码规则 |
| 向导 | 向导页 | MRP 运算 |

## 2. 新增时怎么判断（三个问题）

1. **能不能编辑？** 不能 → 台账/报表/看板/待办/设置/向导；能 → 第 2 问。
2. **有没有明细？** 有 → 加明细表格（两张明细加全明细）；没有 → 单表表单。
3. **有没有状态和审批？** 有 → 套单据动作/审批；没有 → 基础资料的启用/停用。

"销售/采购/财务"这些只是菜单放在哪，不影响组件选择。

## 7. 怎么全面排查功能问题（重点）

### 7.1 问题的根源

功能不是"一个总开关"，而是每个单据在 **前端页面、前端登记表、后端接口、后端登记表** 四个地方各接一次。任何一处漏了，就会出现"这个单生效、下一个单不生效"，而且不报错。

### 7.2 排查分三层

| 层 | 做什么 | 能发现什么 |
|---|---|---|
| **第一层：静态核对** | 拿登记表第 4 栏当"应该有的"，扫页面/登记表/接口当"实际有的"，逐格打勾 | 漏登记、登记了没接线、页面没引用组件 |
| **第二层：运行体检** | 按单据逐项调接口：列表、明细、导出、打印各试一次；用受限角色再试一次 | 后端没过滤、导出/明细绕过权限、数据权限列漏配 |
| **第三层：真实点击** | 选基准单据走全流程，其余单据抽查差异项 | 按钮不显示、控件失效、页面表现问题 |

### 7.3 权限专项（最容易"这个生效、那个不生效"）

四层权限，每层都分前后端两段，缺一段就不完整：

| 权限 | 前端 | 后端 | 常见漏法 |
|---|---|---|---|
| 菜单权限 | 路由守卫 + 菜单配置 | 菜单/接口权限 | 菜单加了没授权 |
| 按钮权限 | 按钮码 | 接口鉴权 | 按钮码没登记（不判定=全显示） |
| 字段权限 | 页面按登记表自动取键、列隐藏 | 列表/报表响应剔除；导出写盘前剔列；打印取数剔除；AI 小助手与自定义报表同一规则 | 页面登记缺失（启动静态体检点名） |
| 数据权限 | 不适用 | 列表/明细/导出/报表各接口过滤 | 各单据过滤列不同（销售员/采购员/制单人/创建人），漏配=全可见 |

**每个单据按 4×4 矩阵逐格验**：菜单/按钮/字段/数据 × 列表/明细/导出/打印。同一套用例用两个角色跑，比对"可见字段、可见按钮、可见行数"，和登记表不一致就是问题。

### 7.4 建议先做"功能体检表"

- 结构：**单据 × 功能 × 状态（已接线 / 未接线 / 不适用）+ 证据（接口/页面/登记表位置）**。
- 期望值来自登记表第 4 栏，实际值来自扫描和接口探测，两者对比出红黄绿。
- 先做静态核对 + 权限专项运行体检，成本最低、见效最快；真实点击沿用现有冒烟用例的思路，按登记表自动生成。
