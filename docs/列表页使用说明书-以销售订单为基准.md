# 列表页使用说明书（基准：销售订单列表）

> 适用对象：所有接入通用列表壳的列表页（当前：销售订单；采购 6 页；库存 6 页）
> 编写时间：2026-09-16　编写依据：**真实运行结果**（真实请求参数 + 真实返回字段，非文档推测）
> 用途：① 新页面接入时的对接契约；② 已接入页面的排查清单（见第 6 节自检表）

***

## 1. 组件概述

> 一句话：列表页通用组件把"单据列表"的标准能力——统计卡片、筛选搜索、表格、分页、列设置、打印、批量操作——统一成一套可复用的壳，页面只需**声明**筛选项与卡片条件，不再各写一套查询区（解决"每个列表页长得不一样、筛选点了没反应、卡片数字对不上"这类重复问题）。

列表页由「统计卡片 + 搜索区 + 表格 + 分页」四段组成，统一由两个通用件提供：

| 通用件    | 业务职责                                                                           |
| ------ | ------------------------------------------------------------------------------ |
| 列表壳    | 页头/统计卡片/搜索区布局/表格/分页/列设置/打印/批量条                                                 |
| 声明式搜索栏 | 按页面声明渲染筛选控件（单据状态 / 日期区间 / 客户 / 供应商 / 员工），只渲染声明过的，**没声明的不渲染**（机制上杜绝"渲染了却点了没反应"） |

页面只做三件声明式的事：声明筛选维度、声明卡片及其筛选条件、把入参交给后端查询工具。

***

## 2. 入参（列表查询）

请求方式：`GET`，参数以下列名称为准（销售订单为例，其它页面同口径）。

### 2.1 分页

| 参数名       | 业务含义 | 类型 | 必填 | 默认 | 取值/说明                                                          |
| --------- | ---- | -- | -- | -- | -------------------------------------------------------------- |
| `current` | 第几页  | 整数 | 否  | 1  | 从 1 开始；**部分老接口 URL 叫** **`/page`** **但参数名仍是本名**，另有 `page` 旧名兜底 |
| `size`    | 每页条数 | 整数 | 否  | 20 | 由"每页条数"下拉给出，选项须与原页面能力一致（原支持 200 的不得收敛掉）                        |

### 2.2 筛选条件

| 参数名                     | 业务含义                     | 类型       | 必填 | 默认     | 取值/说明                                                 |
| ----------------------- | ------------------------ | -------- | -- | ------ | ----------------------------------------------------- |
| `keyword`               | 关键词                      | 文本       | 否  | 空      | **一个框同时匹配多个业务列**（销售订单：单据编号 + 客户名称），后端必须**成组**（见 5.1）  |
| `status`                | 单据状态                     | 文本       | 否  | 空=全部   | 取该单据状态机的真实值（销售订单：草稿/待审核/已生效/已关闭/已取消；**下拉首项固定"全部"**）   |
| `startDate` / `endDate` | 单据日期区间                   | 日期       | 否  | 空=不限   | 格式 `YYYY-MM-DD`；按该页"单据日期"类字段过滤                        |
| `customerId`            | 客户                       | 整数       | 否  | 空      | **精准**（按客户主键），与关键词的模糊匹配互补                             |
| `supplierId`            | 供应商                      | 整数       | 否  | 空      | 同上（采购类页面使用）                                           |
| `employeeId`            | 员工（销售员/采购员/经手人/申请人/领料人…） | 整数       | 否  | 空      | 业务角色名由页面声明；后端映射到该页真实列，**不改表**                         |
| `sortBy` / `sortOrder`  | 排序列 / 方向                 | 文本       | 否  | 各页默认排序 | `sortBy` 必须在**后端白名单**内，不在白名单的列忽略（防注入）；方向 `asc`/`desc` |
| `customSearch`          | 自定义字段搜索                  | 文本(JSON) | 否  | 空      | 由"自定义字段搜索"控件产生，走自定义字段值表                               |

### 2.3 页面专用参数（非通用，按页声明）

| 参数名                                                    | 业务含义                        | 示例页         |
| ------------------------------------------------------ | --------------------------- | ----------- |
| `customerLevel` / `materialId` / `productLineId`       | 看板钻取维度（从数据看板点进来时带）          | 销售订单        |
| `transType` / `stockId` / `batchNo` / `sourceBillType` | 流水台账专用维度                    | 库存流水        |
| `billType`                                             | 同一接口被多单据复用时的类型区分（如领料/退料/补料） | 生产领料、其他出入库等 |

### 2.4 统计卡片数据源入参

卡片统计是**独立请求**，入参极少（通常无筛选入参），但**必须与列表同数据权限口径**。

| 接口                        | 业务含义     | 返回字段（真实）                                                                                                                              |
| ------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/sale/dashboard` | 销售订单卡片统计 | `totalOrders` 总单数、`monthOrders` 本月、`draftOrders` 草稿、`pendingOrders` 待审核、`approvedOrders` 已生效、`closedOrders` 已关闭、`cancelledOrders` 已取消 |

> ⚠ 各模块命名字段不统一（采购用 `monthOrders/monthContracts/monthInbounds…`；库存用 `monthCount/draftCount/pendingCount/approvedCount`）。**接入新页时以该页已消费的字段为准**，不要照抄别模块。

## 3. 出参

### 3.1 统一返回包装

| 参数名       | 类型      | 必填 | 说明                                     |
| --------- | ------- | -- | -------------------------------------- |
| `code`    | Integer | 是  | 业务结果码，`200` 为成功（非 200 时前端提示 `message`） |
| `message` | String  | 是  | 提示信息（成功时为"操作成功"之类）                     |
| `data`    | Object  | 否  | 业务数据体，失败时通常为空                          |

### 3.2 列表数据体 `data`

| 参数名       | 类型      | 必填 | 说明                 |
| --------- | ------- | -- | ------------------ |
| `records` | List    | 是  | 当前页的单据数组（无数据时为空数组） |
| `total`   | Long    | 是  | 满足筛选条件的总条数（分页控件用）  |
| `current` | Integer | 是  | 回显当前是第几页           |
| `size`    | Integer | 是  | 回显每页条数             |

> 下一节「单据对象」字段的类型约定：主键/外键 = 整数；单据编号/名称/状态 = 文本；金额与数量 = 小数；日期 = 文本 `YYYY-MM-DD`；时间戳 = 日期时间；明细 = 数组。

### 3.3 单据对象关键字段（销售订单真实返回，约 90 个字段，按业务分组）

| 分组             | 字段（业务含义）                                                                                                                                                                                            |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 单据标识           | 单据主键、单据编号、单据日期、客户单号、项目号、业务类型、来源单据类型/单号                                                                                                                                                              |
| 往来单位           | 客户主键、客户编号、客户简称、**客户名称**（列表展示用）、联系人、联系电话、收货地址                                                                                                                                                        |
| 责任人/组织         | 销售员主键、**销售员姓名**、部门、经手人（备货人）、制单人/修改人、组织编码                                                                                                                                                            |
| 金额与税务          | 含税总额、税额、折扣率、折扣额、净额、本币总额/税额/净额、已收款额、定金、汇率、是否含税、计税方式                                                                                                                                                  |
| 结算             | 结算方式、付款条件、收款账户、结算账户名、币种                                                                                                                                                                             |
| 收发与物流          | 交货日期、仓库、物流公司、物流单号、运输方式                                                                                                                                                                              |
| 业务标记           | 是否开票、是否样品、是否寄售、发票类型、价格等级                                                                                                                                                                            |
| 状态（**控件联动依据**） | `status` 单据状态、`approvalStatus` 审批状态、`approvedBy/approvedAt` 审批人/时间、`closeStatus` 结案状态、`closedBy/closedAt/closedReason` 结案人/时间/原因、`billBeforeStatus` 重置草稿前状态、`voidedBy/voidedAt/voidReason` 作废人/时间/原因 |
| 关联明细           | `items` 行明细（列表页通常不返回或为空，明细以大字段返回者为空）                                                                                                                                                                |
| 审计             | `createdAt/updatedAt/createdBy/updatedBy`                                                                                                                                                           |

> **注意**：`customerName`（客户名称）可能为空，而 `customerId` 有值 —— 这不是脏数据，部分历史单据只存了主键。因此"按客户名搜不到、按客户下拉能查到"是正常现象（见 5.4）。

### 3.4 统计卡片返回

见 2.4；**卡片值必须来自接口**，禁止页面硬编码（历史问题：销售订单 4 张卡片长期恒为 0）。

## 4. 依赖

### 4.1 前端依赖

| 依赖        | 业务作用                                | 页面是否可省                     |
| --------- | ----------------------------------- | -------------------------- |
| 列表壳       | 卡片/搜索区两栏固定布局/表格/分页/列设置入口/打印入口/批量操作条 | 不可省                        |
| 声明式搜索栏    | 按维度渲染「标签+控件」，标签固定列宽保证换行后逐列对齐        | 不可省                        |
| 自定义字段搜索控件 | 自定义字段的查询条件                          | 可省（页面无自定义字段时）              |
| 列设置抽屉     | 列显示/顺序/宽度，按 `storage-key` 记忆        | 有列设置能力时必须传唯一 `storage-key` |
| 打印预览      | 单据打印（依赖单据类型标识）                      | 可省                         |

### 4.2 后端依赖

| 依赖      | 业务作用                                                         |
| ------- | ------------------------------------------------------------ |
| 列表查询工具  | 分页口径统一（`current` 优先、旧名兼容）、排序白名单、**关键词成组**、日期区间、ID 匹配、员工维度列映射 |
| 数据权限组件  | 按角色数据范围过滤（仅本人/本部门/全部），**列表与卡片必须同一口径**                        |
| 状态机     | 单据状态的合法取值来源（下拉选项必须与之对齐）                                      |
| 自定义字段服务 | 自定义字段定义与值                                                    |
| 字典服务    | 状态/类型等下拉文案与多语言                                               |

### 4.3 下拉数据源接口（页面声明了对应维度就依赖它）

| 维度  | 数据源                | 业务作用          |
| --- | ------------------ | ------------- |
| 客户  | 客户选择项接口（支持关键词远程搜索） | 客户下拉          |
| 供应商 | 供应商选择项接口（同上）       | 供应商下拉         |
| 员工  | 员工选择项接口（同上）        | 销售员/采购员/经办人下拉 |

> 若页面声明了某维度但该数据源不可用，会出现"下拉打不开/搜不到人"——接入时必须逐个点开验证。

## 5. 注意事项（每条都有实证）

1. **关键词必须成组**：一个关键词匹配多列时，后端必须写成"多列条件整体 AND 到其它条件上"。历史缺陷：采购合同曾把两列关键词平铺，导致命中"单据编号"那一支的行**绕过状态筛选、绕过自定义字段、甚至绕过数据权限**（按合同号能搜到别人的单据）。排查口径：`关键词命中某行 + 该行不满足的状态 → 必须 0 条`。
2. **参数名必须两端一致**：历史缺陷：采购订单前端发的是"供应商名称"，后端只认"关键词"，**填了等于没填**。接入时必须核对"页面发什么 = 后端认什么"。
3. **状态选项必须来自状态机真实值**：历史缺陷：采购订单状态页签写的是"已确认/已入库/已完成"，而状态机里根本没有这几个值 → **点了永远 0 条**。
4. **关键词的模糊范围要与提示文案一致**：销售订单关键词框文案是"输入订单号/客户名称搜索"，但库里有 7/58 张单据**客户名称为空、客户主键有值** → 按客户名搜不到。因此客户维度另设**精准下拉**，两者互补，不是重复控件。
5. **数据权限是同一口径**：列表和卡片统计都必须走数据权限，否则会出现"卡片显示 5 条、列表只有 2 条"。
6. **"每页条数"选项不得收敛**：通用壳默认 `[20,50,100]`，页面原本支持 200 条/页的必须显式传入（库存流水已按此处理）。
7. **台账类页面的日期标签要改文案**：通用壳默认标签是"单据日期"，库存流水真实列是"交易日期"，已通过页面声明修正；新接入的台账页同样要传。
8. **排序只认白名单**：不在白名单的排序列会被忽略（防注入），不会报错。若页面的列头可排序但后端白名单没有该列，会出现"点列头没反应"。
9. **卡片点击筛选的语义要分清**：三类卡片——① 状态类（点"草稿"→按草稿筛）② 时间类（点"本月"→按当月筛）③ **清空类**（点"流水总数"→清空条件）。排查时不要假设"点了必带参数"。
10. **卡片值为 0 可能是真值**：库内没有数据时卡片显示 0 是正常的（采购退货、其他出库当前就是 0 张单据），不能据此判定"卡片没接数据"。
11. **改后的运行时验证必须包含**：后端接口真实调用（断言返回与筛选生效）+ 浏览器点击级（页面无控制台报错、点按钮出正确结果），二者缺一不可。
12. **同一文件在一条消息里只做一次编辑**：本项目多次出现"两次编辑被静默丢弃一次"，改完必须复读文件确认落地。
13. **关键词要能按"客户名称"搜——即使单据表里没这个列**：销售类单据表只存客户主键，客户名称在客户档案表。做法由**通用件**统一提供：把"按名称模糊查出的客户主键集合"并入关键词的同一个 OR 组（`(单号 LIKE ? OR … OR 客户主键 IN (…))`），**不允许**各页把搜索框文案改成"只能搜单号"来绕开（那属于掩盖问题）。实测：订单 7 条、报价 3 条、合同 8 条、出库 1 条、发票 1 条均可按客户名称命中。
14. **名称→主键的解析不要套用客户档案的数据权限**：该解析只用于"构造单据筛选条件"，单据可见性由单据自身的数据权限负责；若这里再套一层客户私海/公海权限，会出现"单据明明有这个客户却搜不到"。解析需限条数（现为 500 条上限）且空关键词不查库。

## 6. 自检表（用于排查已接入页面）

| #  | 检查项            | 通过标准                                    |
| -- | -------------- | --------------------------------------- |
| 1  | 页面是否声明了应有的筛选维度 | 维度与业务相符（单据页至少：单据编号/状态/日期 + 该页往来单位或经手人）  |
| 2  | 关键词匹配列         | 与提示文案一致，且**多列已成组**（`关键词+不满足的状态 → 0 条`）  |
| 3  | 状态选项           | 与状态机真实取值一致，首项"全部"，无"永远 0 条"的假选项         |
| 4  | 前端发参 = 后端收参    | 无"发了没人接"的死参数，无"后端支持但前端没发"的漏接            |
| 5  | 状态页签           | 已声明状态下拉后，页签已移除（避免两处控同一条件）               |
| 6  | 卡片数据           | 来自接口、非硬编码；与列表**同数据权限口径**                |
| 7  | 卡片可点击          | 带筛选条件的卡片可点击、当前卡背景高亮（`#dfe4fd`）、再点取消     |
| 8  | 分页             | 入参名正确（`current` 优先、旧名兼容）、每页条数选项未收敛      |
| 9  | 排序             | 列头可排序列都在后端白名单内                          |
| 10 | 筛选控件标签         | 每个控件都有左侧标签；台账页日期标签文案与真实列相符              |
| 11 | 栅格对齐           | 窗口拉窄让筛选换行后，两行**逐列对齐**；右侧按钮/列设置位置不动且贴右边框 |
| 12 | 被引用点未被打断       | 打印（单据类型）、导出（参数名）、看板钻取（参数名）均与接入前一致       |
| 13 | 运行时            | 后端接口通 + 浏览器点击级通 + 控制台 0 报错              |
