# 小楷助手 · 销售订单操作说明书

> 适用范围：ERP 智能助手「小楷」（右下角 🤖 浮球 + 右侧抽屉）对【销售订单】（billType = `SALE_ORDER`）的全部可操作能力。
> 文档性质：组件使用说明书（守则 09 五要素）+ 销售模块通用插件适配的「样板单」参考。
> 最后更新：2026-09-18
>
> **适配范围（2026-09-18 通用插件适配完成）**：以下能力已从销售订单**推广到销售模块全部 6 种单据** ——
> 销售报价单（`SALE_QUOTE`）、销售订单（`SALE_ORDER`）、销售合同（`SALE_CONTRACT`）、
> 销售出库单（`SALE_DELIVERY`）、销售退货单（`SALE_RETURN`）、销售发票（`SALE_INVOICE`）。
> 各单据的查询/条件搜索/明细行编辑/流程动作均已可用；**主体以销售订单（`SALE_ORDER`）为例说明，
> 其余单据把下文** **`SALE_ORDER`** **替换为对应 billType 即可**。差异见「十四、销售模块 6 种单据适配对照」。

***

## 一、组件概述

小楷助手对销售订单提供**六类能力**：查询、按条件搜索、明细行查看/编辑、流程动作（提交/审核/驳回/作废等）、下推（转出库/转采购）、界面导航。所有**写操作**默认弹「确认卡片」由用户拍板后才会真正执行，且 AI 代执行的操作会额外记一条「AI助手代执行」审计日志，可追溯、可回退（审批有重置草稿、作废有反作废、结案有反结案）。

核心原则（写死，勿回退）：

1. **主键优先**：所有操作先查到 `orderId`（数字主键），**严禁把单号当主键**传。
2. **明细行不改派生列**：金额/税额/净额/合计由整单保存链路自动重算，AI 只允许改「单价/数量/税率/折扣率」4 个字段。
3. **走原 Service 整单保存**：不直连子表，保证重算、设置中心校验、状态检查（已生效/已完结不可改）与界面完全一致。

## 三、查询销售订单

### 入参

| 参数名       | 类型     | 必填 | 说明                                                          |
| --------- | ------ | -- | ----------------------------------------------------------- |
| `keyword` | string | 否  | 单号或客户名关键字（后端按 `searchFields` = orderNo / customerName 模糊匹配） |
| `filters` | array  | 否  | 条件筛选，见「四、按条件搜索」                                             |

### 出参

| 参数名            | 类型      | 说明                           |
| -------------- | ------- | ---------------------------- |
| `orderNo`      | string  | 销售订单号                        |
| `customerName` | string  | 客户名称（由 customerId 回查补全，非冗余列） |
| `totalAmount`  | decimal | 合计金额                         |
| `status`       | string  | 单据状态（草稿/已生效等）                |
| `orderDate`    | date    | 订单日期                         |

### 依赖

- 后端 `AiCrudAgentService` 的 `EntityCrudConfig`（`QUERY_SALE_ORDER`），主键字段 `orderId`、主键列 `order_id`。

### 注意事项

- 返回的 `orderId`（数字主键）是后续动作/明细编辑的**唯一定位依据**，禁止把单号说给用户或当主键用。

## 四、按条件搜索（filters）

`query_sale_order` 支持 `filters` 白名单条件（字段必须实体真实存在 + 在白名单内，非法条件直接报错、不静默忽略）。

| 可筛字段           | 说明            |
| -------------- | ------------- |
| `status`       | 单据状态（草稿/已生效…） |
| `orderNo`      | 单号            |
| `customerId`   | 客户主键          |
| `orderDate`    | 订单日期          |
| `deliveryDate` | 交货日期          |
| `totalAmount`  | 合计金额          |
| `closeStatus`  | 结案状态          |

运算符 `op`：`eq / ne / gt / ge / lt / le / like / between`（between 传两个值）。

### 注意事项

- **禁止**「拉全量自己筛」——返回有上限会漏数据，必须传 `filters` 走服务端条件。

### 入参

| 参数名        | 类型      | 必填 | 说明                 |
| ---------- | ------- | -- | ------------------ |
| `billType` | string  | 是  | `SALE_ORDER`       |
| `billId`   | integer | 是  | 订单主键 `orderId`（数字） |

### 出参（每行）

| 参数名                     | 说明                      |
| ----------------------- | ----------------------- |

| 数量 / 单价 / 折扣率 / 税率      | 可改字段现值                  |

### 依赖

- `SaleOrderItemHandler`（`ai/bill/impl/SaleOrderItemHandler.java`）。

### 注意事项

- 编辑明细前**必须先 list** 看清行号与现值，不要猜行号。

## 六、编辑明细行（bill\_item\_update）

### 入参

| 参数名                 | 类型      | 必填  | 说明                         |
| ------------------- | ------- | --- | -------------------------- |
| `billType`          | string  | 是   | `SALE_ORDER`               |
| `billId`            | integer | 是   | 订单主键 `orderId`             |
| `itemId` / `lineNo` | integer | 二选一 | 定位目标行（明细行ID 或 行号）          |
| `patch`             | object  | 是   | 要改的字段，如 `{"unitPrice": 1}` |

### 可改字段白名单（仅 4 个）

| 字段             | 中文  | 约束    |
| -------------- | --- | ----- |
| `unitPrice`    | 单价  | ≥0，数字 |
| `quantity`     | 数量  | ≥0，数字 |
| `taxRate`      | 税率  | ≥0，数字 |
| `discountRate` | 折扣率 | ≥0，数字 |

### 出参

- 改前→改后对比（单价/数量/税率/折扣率 + 该行金额 + 单据合计），如「已修改【销售订单】SO-… 第 1 行：单价 0.00 → 1，该行金额 0.00 → 1.00，单据合计 0.00 → 1.00」。

### 依赖

- `SaleOrderService.saveOrderWithItems(order, items)`（整单保存，重算金额/税额/合计 + 校验 + 状态检查）。

- 权限复用 `BillActionPermissionResolver`。

### 注意事项

- **金额/税额/净额/合计不要传**，系统自动重算。

- 已生效 / 已完结的单据会被保存链路拦截（与界面一致）。

- 用户没指明哪一行时，先问清楚再调，不要猜。

## 七、流程动作（bill\_action）

### 入参

| 参数名        | 类型      | 必填 | 说明           |
| ---------- | ------- | -- | ------------ |
| `billType` | string  | 是  | `SALE_ORDER` |
| `billId`   | integer | 是  | 订单主键         |
| `action`   | string  | 是  | 见下表          |
| `reason`   | string  | 条件 | 驳回/关闭/作废时必填  |

### 支持的动作（10 个）

| action           | 中文  | 需 reason | 说明                |
| ---------------- | --- | :------: | ----------------- |
| `submit`         | 提交  |     否    | 未开审批直接生效，开审批进入待审批 |
| `approve`        | 审核  |     否    | 存在审批任务时优先走审批引擎    |
| `reject`         | 驳回  |     是    | 存在审批任务时优先走审批引擎    |
| `reverseApprove` | 重置草稿 |     否    | <br />            |
| `close`          | 关闭  |     是    | <br />            |
| `closeOrder`     | 结案  |     否    | <br />            |
| `reopen`         | 反结案 |     否    | <br />            |
| `void`           | 作废  |     是    | 不可逆动作，强制确认        |
| `unvoid`         | 反作废 |     否    | <br />            |
| `delete`         | 删除  |     否    | 不可逆动作，强制确认        |

### 出参

- `success` / `message`（如「已对【销售订单】SO-… 执行『提交』」）。

### 依赖

- `BillActionRegistry` 能力矩阵（方法名 + 精确参数类型反射调度）、`BillActionPermissionResolver`（权限）、`ApprovalRuntimeService`（审批引擎）、`SysOperateLogService`（审计）。

### 注意事项

- 执行**不支持的动作**会返回该单据支持的动作清单 + 可下推目标，请据此改调用，不要臆测。

- 驳回/关闭/作废必须带 `reason`。

- 需要额外业务参数的动作（如发货需要快递单号）会明确引导到界面，AI 不硬编。

## 八、下推（bill\_pushdown）

销售订单可下推生成下游单据（已核实存在后端接口）：

| 目标单据  | 目标 billType      | 后端方法             |
| ----- | ---------------- | ---------------- |
| 销售出库单 | `SALE_DELIVERY`  | `pushToDelivery` |
| 采购订单  | `PURCHASE_ORDER` | `pushToPurchase` |

### 注意事项

- **下推无任何反动作**（历史上已确认），下推出错只能人工删/作废下游单。

- 销售订单 → 销售发票 属于「后端无生成接口」关系，只能引导到界面选单（不自动生成）。

## 十一、权限

- **默认 menu 模式**：需要 `sale:orders` 菜单权限码（与 `sys_menu.permission_code` 严格一致），管理员或通配符 `*` 直接放行。

- **action 模式**（`ai.bill.permission.mode`，默认关闭）：按角色按钮权限码判定，启用前需先修正按钮码拼接。

- 数据权限：销售角色默认只能看销售数据（`AiDataScope` 注入）。

***

## 十二、确认机制与审计

- 写操作（明细编辑/流程动作/下推）默认弹「确认卡片」。

- 「AI 写操作需人工确认」开关（`ai.confirm.write.enabled`，默认 true）：关闭后**可逆**动作（提交/审核/驳回/重置草稿/下推等）免确认；**删除/作废等不可逆动作仍强制确认**。

- AI 代执行操作额外写一条操作日志（模块=`AI小助手`、姓名=`账号（AI助手代执行）`），在「系统 → 操作日志」搜「AI助手代执行」可筛出全部记录。

***

## 十三、边界与不做（本期）

- **不做**：新建销售订单（需界面补录明细）、打印/导出（浏览器打印对话框限制）、批量操作、一键撤销。

- **已知限制**：下推无反动作；详情页审批记录不识别 AI（审计只能定位 + 人工回退）；明细行编辑只开放 4 个字段（金额类派生列由保存链路重算，不允许 AI 直改）。

## 十四、销售模块 6 种单据适配对照

| 单据    | billType        | 查询/条件搜索 | 明细行编辑 | 明细可改字段       | 明细主键 / 行序字段                         | 保存链路                    |
| ----- | --------------- | :-----: | :---: | ------------ | ----------------------------------- | ----------------------- |
| 销售报价单 | `SALE_QUOTE`    |    ✅    |   ✅   | 单价/数量/税率/折扣率 | `quoteItemId` / `lineNo`            | `saveQuoteWithItems`    |
| 销售订单  | `SALE_ORDER`    |    ✅    |   ✅   | 单价/数量/税率/折扣率 | `orderItemId` / `lineNo`            | `saveOrderWithItems`    |
| 销售合同  | `SALE_CONTRACT` |    ✅    |   ✅   | 单价/数量/税率/折扣率 | `itemId` / **`sortNo`（无 lineNo 列）** | `saveContractWithItems` |
| 销售出库单 | `SALE_DELIVERY` |    ✅    |   ✅   | 单价/数量/税率/折扣率 | `deliveryItemId` / `lineNo`         | `saveDeliveryWithItems` |
| 销售退货单 | `SALE_RETURN`   |    ✅    |   ✅   | 单价/数量/税率/折扣率 | `returnItemId` / `lineNo`           | `saveReturnWithItems`   |
| 销售发票  | `SALE_INVOICE`  |    ✅    |   ✅   | 单价/数量/税率/折扣率 | `invoiceItemId` / `lineNo`          | `saveInvoiceWithItems`  |

### 条件搜索白名单（每种单据各自）

| 单据    | 可筛字段                                                                                       |
| ----- | ------------------------------------------------------------------------------------------ |
| 销售报价单 | status / quoteNo / customerId / quoteDate / deliveryDate / totalAmount / closeStatus       |
| 销售订单  | status / orderNo / customerId / orderDate / deliveryDate / totalAmount / closeStatus       |
| 销售合同  | status / contractNo / customerId / contractDate / deliveryDate / totalAmount / closeStatus |
| 销售出库单 | status / deliveryNo / customerId / deliveryDate / totalAmount / closeStatus                |
| 销售退货单 | status / returnNo / customerId / returnDate / totalAmount / closeStatus                    |
| 销售发票  | status / invoiceNo / customerId / invoiceDate / totalAmount / closeStatus                  |

### 实现机制（插件式，加单据不改工具代码）

1. **明细行编辑**：实现 `BillItemHandler` 接口 + 标 `@Component` → `BillItemRegistry` 自动收集，
   工具（`bill_item_list` / `bill_item_update`）自动支持，**无需改工具代码**。
2. **条件搜索**：在 `AiCrudAgentService` 对应 `EntityCrudConfig` 加 `filterFields` 白名单即可。
3. **流程动作 / 下推**：由 `BillActionRegistry` 能力矩阵驱动，6 种单据原本就已登记。

### 合同明细的三处差异（已核实源码，勿混淆）

1. 明细主键字段是 `itemId`（列 `item_id`），不是 `contractItemId`；
2. **明细没有** **`line_no`** **列**，行序字段是 `sortNo`（列 `sort_no`）→ 适配器 `lineNoField()` 返回 `sortNo`；
3. 明细的 `unit` 是**真实列**（其余销售单据是 `@TableField(exist=false)` 展示字段）。
