# 13 低级缺陷防线

## 这套测试解决什么问题

只抓"用户一眼就能看见"的低级问题，不碰业务逻辑：

- 页面打不开、白屏、跳 403
- 列表有数据却渲染成空白，或干脆不显示空态
- 按钮点了没反应（方法没定义、改名漏改）
- 新增页打开了但字段没渲染
- 接口 500、页面报 `undefined` / `NaN` / `[object Object]`
- 后端方法空实现（接口返回成功，实际什么都没做）

多开关组合、跨模块联动、"某种状态下才出错"这类复杂问题，不在这套里，走 `12-销售订单测试设计` 那种状态迁移/组合用例。

## 四层防线

| 层 | 命令 | 抓什么 | 耗时 | 什么时候跑 |
|---|---|---|---|---|
| L0 静态自查 | `npm run check:lowlevel` | 模板绑定的方法不存在、函数重复声明、后端空实现/未实现占位 | 秒级 | 每次改完代码、提交前 |
| L1 页面覆盖 | `npm run test:smoke:pages` | 每个菜单页能打开、不白屏、无占位符、无 500 | 5–10 分钟 | 每天 / 合并前 |
| L2 交互冒烟 | `npm run test:smoke:lowlevel` | 列表渲染与空态、新增按钮有反应、新增页字段渲染、运行时报错 | 10–15 分钟 | 每周 / 交付前 |
| L3 单据闭环 | `npm run test:smoke:loop` | 34 张单据新增→保存→回读→提交→审核→反审 | 30 分钟+ | 交付前 / 大改后 |

另外三类专项静态检查，改动相关模块时跑：

- `npm run check:dropdown` 下拉字段定义与接口是否对得上
- `npm run check:relations` 推单关系（来源/去向）登记是否完整
- `npm run check:permissions` 页面按钮权限矩阵是否与动作登记一致

## L0 静态自查怎么判

**红灯（退出码 1，必须修）**

1. 模板里绑定的事件处理函数在 script 里不存在——按钮点了没反应、控制台报 "is not a function"。
2. 同一文件里函数重复声明——后一个覆盖前一个，行为不可预期（批量改代码后高发）。
3. 后端空方法（无 `@Override`、非 record、非抽象类）——接口通但没做事。

**黄灯（提示，逐条确认）**

- 后端"暂未实现"占位：确认是业务上明确不支持（应给出清晰提示），还是漏做。
- 模板硬编码中文：不影响运行，按项目规范应改 `$tt`。

## L2 交互冒烟怎么判

每个模块用它自己的账号登录，逐页检查：

| 检查点 | 判定 |
|---|---|
| 表格列头 | 少于 2 列判失败（列没渲染） |
| 无数据 | 必须出现"暂无数据"类空态，否则用户看到一片空白 |
| 新增按钮 | 点击后地址变化或弹出弹窗，两者都没有判失败 |
| 新增页表单 | 控件少于 3 个判失败（字段没渲染） |
| 运行时报错 | console.error / pageerror / 5xx 任一出现判失败 |

**安全边界**：这套用例只读——只打开页面和新增页，不保存、不提交、不删改。默认只在 localhost 上点「新增」；对远端环境只做列表渲染检查，除非显式设置 `E2E_ALLOW_REMOTE_CLICK=1`。

## 怎么跑

```powershell
cd D:\erp\prodsrc\智能ERP-项目\frontend

npm run check:lowlevel                 # L0，改完代码就跑
npm run test:smoke:prepare             # 首次：生成测试账号（只需一次）
npm run test:smoke:pages               # L1
npm run test:smoke:lowlevel            # L2
```

指定环境与模块：

```powershell
$env:E2E_BASE_URL = "http://localhost:3000"
$env:E2E_MODULE_FILTER = "basedata,sale"   # 只跑基础资料与销售
npm run test:smoke:lowlevel
```

两个常用开关：

```powershell
# 本机浏览器版本与 Playwright 不匹配时，直接指定已有 Chromium，免去下载
$env:PLAYWRIGHT_CHROMIUM_EXECUTABLE = "D:\erp\playwright-browsers\chromium-1255\chrome-win64\chrome.exe"

# 只查前 8 个页面，快速验证用例本身是否正常（约 1.5 分钟）
$env:E2E_LOWLEVEL_MAX_PAGES = "8"
```

结果落在 `tests/smoke/.out/07-lowlevel-result.json`，逐模块记录检查页数与失败项。

```
| D-001 | L0 静态 | 销售目标页 | 点表头排序报 onCompanySortChange is not a function | 打开销售目标→点公司列排序 | b9e45d0 后 | 已修，排序正常 |
```

## 首次执行抓到的真实问题

- **销售目标页排序失效**：模板绑定 `onCompanySortChange` / `onEmpSortChange`，脚本里实际定义的是 `handleSortChange` / `handleEmpSortChange`。点击表头排序会报错，排序不生效。属于典型的"改名漏改"，已修复。

## 这套不管什么

- 多开关组合、状态流转分支：见 `12-销售订单测试设计` 的状态迁移与成对组合用例。
- 金额精度、库存一致性：见 `03-库存管理`、`08-财务管理` 的边界值用例。
- 权限矩阵：见 `02-系统设置` 与 `check:permissions`。
