# 物流监控模块操作手册

> 适用版本：智能ERP系统
> 文档说明：本手册详细介绍智能ERP「物流监控」模块（Dashboard 物流看板）的功能、界面布局和操作步骤。物流监控模块通过对接顺丰、京东、圆通、申通、中通、韵达、极兔等主流快递的物流轨迹接口，提供销售出库与采购到货的「在途量-异常量-签收量」全局视图、快递单状态统计表、运输时效分布、按客户/承运商的运单列表与异常追溯功能，是销售跟单、客服、仓库、采购四个岗位的日常运维看板。

## 1. 模块概述

物流监控模块（路径 `/logistics/dashboard`）是智能ERP系统「出库-配送-到货签收」全链路的可视化仪表盘。它与 03-销售管理模块（销售发货）、04-采购管理模块（采购到货）、05-库存管理模块（销售出库单/采购入库单）深度联动：

- **数据来源**：销售出库（`SO Issue`）后生成的销售发货单（带快递单号），以及采购订单（`PO`）对应供应商发货记录（我方采购到货前的在途）。
- **查询频率**：对接快递 100 或各快递商开放平台 API（顺丰 BSP、京东物流 VOP、菜鸟裹裹等），每 15 分钟拉一次在途运单最新状态，已签收运单仅拉 1 次后停更。
- **异常识别**：自动判别 6 类物流异常：超期未签收、快递返回「签收失败」「拒收」、超时未更新轨迹、清关/安检问题、揽收失败、发货后 24h 无轨迹。异常运单进入异常列表并在看板顶部红字提醒。

模块页面为单页 Dashboard 看板（无二级路由），自上而下 4 个核心区块：

1. **顶部全局统计行（7 张 KPI 卡）**：在途运单总数、今日发货数、异常数、已签收数（本月）、在途金额、3 日将到件、异常占比。
2. **快递单状态统计表（表格）**：按「快递公司」维度拆分明细（7 种标准快递+其他），展示：运单数、揽收中、运输中、派送中、已签收、异常数、异常率、平均时效。
3. **运输时效分布图**：柱状图 + 折线组合图（X 轴=快递公司，主 Y 轴=平均时效天，次 Y 轴=按时率%）。
4. **运单列表（默认全量+筛选+分页+详情）**：左侧「客户/承运商/状态/时间」筛选区，右侧运单表格（可点行展开轨迹），底部分页。顶部有「导出全部/导出筛选」两个 Excel 按钮。

## 2. 进入方式与权限说明

### 2.1 进入方式

1. 登录系统 → 左侧导航菜单「物流监控」→ 进入看板（无二级菜单，单页）。
2. 若管理员在工作台自定义配置了「物流监控快速入口」卡片，也可从工作台直接跳转。

### 2.2 权限说明

| 角色 | 权限范围 |
|------|----------|
| `ADMIN` / `WAREHOUSE` 仓库管理员 | 全量查看所有运单 + 导出。 |
| `SALES_MANAGER` 销售经理 | 查看团队销售相关出库的运单（仅看本部门业务员的客户）。 |
| `SALES` 普通业务员 | 仅看本人负责客户的出库运单（默认按业务员过滤）。 |
| `PURCHASE_MANAGER` / `PURCHASE` 采购 | 仅看与采购相关的「供应商发货」在途（到货前追踪）。 |
| `CUSTOMER_SERVICE` 客服 | 全量查看（仅 7 项 KPI 卡 + 运单列表，禁止导出 Excel）。 |
| 其他角色（财务/生产/质量） | 默认无权限，若需要请联系管理员。 |

> 注意：销售角色只能查看销售出库的发货单，看不到采购到货的供应商发货运单；反之亦然（岗位隔离）。ADMIN/WAREHOUSE/客服 三个角色跨两边都能看。

## 3. 通用约定与状态体系

### 3.1 快递标准编码

| 编码 | 中文名称 | 常用颜色（tag） |
|------|----------|------------------|
| SF | 顺丰速运 | 黑色 #333333 |
| JD | 京东物流 | 红色 #e1251b |
| YTO | 圆通速递 | 蓝色 |
| STO | 申通快递 | 深黄 |
| ZTO | 中通快递 | 蓝色系 |
| YD | 韵达快递 | 橙色 |
| JT | 极兔速递 | 品红 |
| EMS | 邮政 EMS | 墨绿 |
| DB | 德邦 | 深蓝 |
| OTHER | 其他（平台物流、专线） | 灰色 |

### 3.2 运单状态定义（5 大标准状态 + 异常）

| 状态 | 中文 | 解释（判定口径） |
|------|------|------------------|
| `pending` | 待揽收 | ERP 已写入快递单号，尚未从快递商 API 收到「已揽收」轨迹。 |
| `picked` | 已揽收/运输中 | 已揽收且未到目的地分拨（含中转所有节点）。 |
| `delivering` | 派送中 | 快递商 API 返回「派件中 / 派送中」关键字。 |
| `signed` | 已签收 | API 返回「签收 / 本人签收 / 代收」关键字。 |
| `returned` | 退回中/已退回 | API 返回「退回 / 拒收」关键字。 |
| `exception` | 异常 | 以上状态之外的异常情况（超期未签、清关问题、滞留超时、签收失败等），系统自动判断并打标签。 |

### 3.3 异常类型（6 类）

| 异常码 | 中文 | 触发条件 |
|--------|------|----------|
| EX-01 | 超期未签收 | 预计到达日 ≤ 今日 且 状态未 =signed（默认按快递公司标准时效计算预计到达日）。 |
| EX-02 | 签收失败 / 拒收 | 轨迹包含「签收失败」「无人接听」「拒收」「客户要求退回」等关键词。 |
| EX-03 | 轨迹滞留超时 | 最新一条轨迹的时间 > 24h 前，且状态仍在运输中/派送中（无新节点）。 |
| EX-04 | 安检/清关异常 | 轨迹包含「安检」「扣关」「海关」「退回发件地」等关键词。 |
| EX-05 | 揽收失败 | `pending` 超过 48h 仍未收到「已揽收」轨迹。 |
| EX-06 | 发货后无轨迹 | 销售发货单填写单号后 24h 内，API 查不到任何轨迹记录（可能单号错）。 |

## 4. 顶部全局统计行（7 项关键指标）

### 4.1 功能说明

页面首行 7 张横向紧凑 KPI 卡（`v-for="card in kpiCards"` 生成，`el-statistic` 风格），数据来源为后端聚合。每张卡片支持点击跳转到下方运单列表并自动应用对应筛选条件。

| 序号 | 指标名称 | 说明 | 筛选行为（点击卡片时） |
|------|----------|------|------------------------|
| 1 | 在途运单总数 | 状态 ≠ signed & ≠ returned（即 pending+picked+delivering+exception）。 | 运单列表 = 状态 ≠ 签收/退回。 |
| 2 | 今日发货数 | 今日 00:00:00 至今创建的发货单（销售发货或采购发货），不论揽收与否。 | 运单列表 = 发货日期 = 今日。 |
| 3 | 异常数 | 状态 = exception 的运单数（红色大字，红色背景边框卡片）。 | 运单列表 = 异常（打开列表首行就有所有异常）。 |
| 4 | 本月已签收数 | 当月 1 日 00:00 至今 signed 状态的运单数。 | 运单列表 = 状态=已签收 + 时间=本月。 |
| 5 | 在途总金额 | 所有在途运单对应原销售发货单的未税总金额合计（¥ 千分位）。 | 跳转列表 = 在途（同第1项筛选）。 |
| 6 | 3 日将到件数 | 预计到达日 ∈ [今日+1, 今日+3] 的运单数，仍为未签收。 | 运单列表 = 预计到达日 ∈ 未来 3 天 & 状态≠签收。 |
| 7 | 异常占比 | 异常数 / 在途总数 * 100%；≥ 5% 红字显示，3%~5% 橙字，<3% 绿字。 | 跳异常列表（同第3项筛选）。 |

### 4.2 界面描述

7 张卡片一行，响应式：大屏 7 列并排；中屏自动换行（每行 3~4 张）；小屏单张一列堆叠。每张卡内部结构：
- 左上角小图标（`Van/TrendCharts/Warning/CircleCheck/Money/Calendar/Histogram` 等彩色 Element Plus 图标）。
- 顶部黑色大数字（`el-statistic` 组件风格），千分位格式化。
- 底部灰色小字标签（指标名称 + 单位）。

异常数卡片有红色边框 + 脉冲动画（`pulse-red`），紧急时一眼可见。

### 4.3 操作步骤

1. 打开物流监控页面，页面加载时自动拉取 7 项 KPI 数据（`v-loading` 显示骨架动画，通常 1~3 秒）。
2. 优先观察：
   - **异常数**（第3张，红卡）：0=正常，>0=点击卡片 → 跳运单列表自动过滤仅异常。
   - **异常占比**（第7张）：≥ 5% 立即介入复盘。
3. 点击任意 KPI 卡 → 页面自动滚动到下方「运单列表」，并应用对应筛选条件（左侧筛选控件同步更新状态值）。
4. 若数据有延迟，可点击 KPI 卡右上角的小「刷新」图标（每 30 秒可手动点一次）。

### 4.4 注意事项

- **在途总金额口径**：为销售发货单（含税/未税由公司的「金额展示规则」系统参数定，默认未税）与采购采购单金额的总和，非成本价。财务对账请以财务模块应收账款实际为准。
- **KPI 与列表不一致**：KPI 为聚合缓存（5 分钟刷新），列表为实时查询。若数字偏差较大，请手动点刷新按钮；超过 15 分钟偏差仍大请联系运维检查物流接口任务。
- **3 日将到件预计到达日计算**：顺丰/京东按 API 给出的标准时效（通常 1~2 天）；其他快递按历史 30 天该快递公司「揽收→签收」平均天数估算（首次使用时若数据不足，默认按 3 天估算，可能偏高/偏低）。

## 5. 快递单状态统计表（按快递维度）

### 5.1 功能说明

按快递商聚合展示本月至今的所有运单状态分布，用于快速定位「哪家快递异常率高、哪家平均时效长」等快递商层面的运维问题。

表格维度：按快递公司编码（SF/JD/YTO/STO/ZTO/YD/JT/EMS/DB/OTHER）10 行。

### 5.2 界面描述

标准 `el-table`，9 列（快递公司 + 6 状态列 + 异常率 + 平均时效）：

| 列名 | 说明 |
|------|------|
| 快递公司 | 顺丰/京东/圆通…彩色 tag 图标（SF 黑底白字，JD 红底等，对应 3.1 表格）。 |
| 运单总数 | 本月快递该公司的所有运单量。 |
| 待揽收 | `pending` 计数。 |
| 运输中 | `picked` 计数。 |
| 派送中 | `delivering` 计数。 |
| 已签收 | `signed` 计数。 |
| 异常数 | `exception` 计数（异常 6 类之和）；>0 的单元格用红色背景强调。 |
| 异常率 | `异常数 / 运单总数 * 100%`；红色渐变：0 透明 → 1%~4% 浅橙 → ≥ 5% 红色背景。 |
| 平均时效（天） | 该公司本月所有已签收运单的「揽收时间 → 签收时间」的平均值，保留 1 位小数；> 3 天显示橙字，> 5 天显示红字。 |

行规则：
- 总计行：表尾自动合计「运单总数 / 各状态 / 异常数」；异常率与平均时效按加权平均计算（`SUM(异常数)/SUM(运单总数)` 与按运单数加权的平均时效）。
- 点击任意数据行：行高亮，下方运单列表自动筛选为该快递商（左侧「快递商」下拉框同步更新）+ 月份不变。
- 顶部「导出」按钮：按当前表（10 行+合计）导出 Excel。

### 5.3 操作步骤

1. 页面自动加载统计表后，扫描「异常率」列：
   - 哪家快递异常率 ≥ 5%（红字 / 深红背景）→ 立即点该行 → 跳转运单列表只看该快递，优先处理异常。
   - 哪家快递「平均时效」> 5 天（红字）→ 点该行查看明细（是否为偏远地区集中导致）。
2. 点击「导出 Excel」按钮 → 浏览器下载「物流快递状态统计表_YYYYMMDD.xlsx」（含 10 行明细+汇总行）。
3. 若本月无该快递的运单，表格中该快递行显示 0/0/0…（不隐藏行，方便横向对比）。

### 5.4 注意事项

- **本月口径**：按「发货日期」所在月份统计（非签收日期）。即 8 月 31 日发货、9 月 2 日签收的运单，会计入 8 月份的「运单总数」+「已签收」中；9 月份看板上看不到这张单。
- **时效计算只针对已签收**：未签收运单不参与「平均时效」分母（否则会被在途单虚高）。
- **OTHER（其他快递）**：通常为客户指定的专线/小物流，无标准 API，轨迹需人工维护（详见 Q6）。OTHER 的状态和异常通常不准确，不作为快递商考核依据。

## 6. 运输时效分布图（平均时效/按时率）

### 6.1 功能说明

以图表形式直观对比 10 家快递的平均时效（天）和按时送达率（%）。用于：
- 管理层月度快递商考核（横向对比）。
- 识别异常时效的快递，辅助供应商切换/降本。
- 销售给客户承诺到货时间时的数据依据。

图表类型：ECharts 双轴组合图：
- 主 Y 轴（左）：柱状图 = 平均时效（天，柱越短越好）。
- 次 Y 轴（右）：折线图 = 按时率（%，线越高越好）。
- X 轴：10 家快递（与统计表一致）。

### 6.2 界面描述

`el-card` 包裹 ECharts DIV（`height=380px`，自适应父容器宽度）。
- 柱体颜色按平均时效分档：< 2 天绿 / 2~3 天蓝 / 3~5 天橙 / >5 天红。
- 按时率折线为粗红色线条（`lineStyle: width=3, color=#e74c3c`），每个数据点显示实际百分比数值标签。
- 图例：右上「平均时效（天）」「按时率（%）」，点击可切换显示/隐藏。
- Tooltip：悬停在某快递上，显示快递名称 + 平均时效具体值 + 按时率具体值 + 样本运单数。
- 右上角「下载 PNG」按钮，可保存图表截图。
- 右下角时间范围切换：默认「近 30 天」→ 可切换「近 7 天 / 近 90 天 / 全部」。

### 6.3 操作步骤

1. 页面打开后，图表默认拉取「近 30 天」数据渲染。
2. 鼠标悬停某柱/折点 → 出现 Tooltip。
3. 切换底部时间范围（近 7 天/30 天/90 天/全部）→ 图表和上一节的「统计表」联动刷新（注：统计表默认按月，切时间范围后统计口径随之变化，变成所选时间范围内）。
4. 若需要保存截图，点「下载 PNG」→ 浏览器弹出下载图片。
5. 点击图例中的「平均时效」或「按时率」→ 隐藏对应图层（便于单独看另一个）；再次点击可重新显示。

### 6.4 注意事项

- **按时率定义**：运单的「实际签收时间 - 揽收时间」 ≤ 「该快递公司标准时效 + 1 天」 记为按时。标准时效值存储在系统参数中（默认 SF=2d, JD=2d, 三通一达=3d, EMS=4d, 德邦/OTHER=5d），可由管理员调整。
- **样本量过小的快递**：运单 < 10 单的快递在图表中有半透明灰色蒙层 +「样本不足，仅供参考」文字标签，不建议纳入考核。
- **图表与 KPI 行数据不完全一致**：KPI 行按「发货时间」月份；图表按所选时间范围（如近 30 天 = 跨月）→ 口径不同属正常。

## 7. 运单列表（按客户/承运商筛选）

### 7.1 功能说明

看板最下方的核心明细区域，支持「按客户/供应商/承运商/状态/时间范围/异常类型」多维筛选 + 分页 + 轨迹详情展开 + 导出 Excel。

数据来源：所有快递单（销售发货产生的 + 采购供应商发货录入的），根据角色权限过滤。

### 7.2 界面描述

上下两部分：**左侧筛选栏 + 右上导出按钮** + **中间表格 + 底部分页**。

#### 左侧筛选区（1/4 宽度）
- **客户名称**（输入框，`placeholder=客户名称/简称`，支持模糊搜索，仅销售/仓库/客服角色显示；采购角色不显示）。
- **供应商名称**（输入框，仅采购/仓库/客服角色显示）。
- **快递商**（下拉多选，9 家标准+OTHER，可多选）。
- **运单状态**（下拉单选：全部/待揽收/已揽收/派送中/已签收/退回中/异常）。
- **异常类型**（下拉多选：6 类异常 EX-01~EX-06，仅状态选中「异常」或「全部」时可用）。
- **发货日期范围**（`el-date-picker type=daterange`，默认近 14 天）。
- **运单号**（精准输入）。
- **查询 / 重置** 按钮。

#### 右上操作按钮区
- **导出全部**（灰色副按钮）：导出当前所有运单（无论筛选），Excel。
- **导出筛选结果**（蓝色主按钮）：按当前筛选条件导出 Excel。
- **刷新**（小按钮）：重新拉取列表数据。

#### 运单表格
`el-table`，固定左列 3 列（可展开行 + 复选框 + 快递单号）、固定右列 操作列。列：
- **展开按钮**（`type=expand`）：点击展开轨迹详情（内嵌 Accordion 手风琴）。
- **勾选框**（多选）：批量导出或标记已处理。
- **运单号**（左固定，加粗；可点击整列复制到剪贴板，ElMessage 提示「已复制」）。
- **关联业务**（销售发货单 / 采购到货单 → 带路由链接，蓝色可点击跳转到对应单据详情页）。
- **客户/供应商名称**（根据单类型显示客户或供应商）。
- **快递商**（彩色 tag）。
- **状态**（彩色 tag：待揽收灰/运输中蓝/派送中蓝稍浅/已签收绿/退回中红/异常红且带「异常类型」子标签）。
- **发货时间**（可排序）。
- **最新轨迹时间**（可排序）。
- **预计到达日**（已过期变红字）。
- **签收时间**（未签收显示 `-`）。
- **收货城市**（文本）。
- **金额**（可选，发货单金额）。
- **业务员 / 采购员**（责任归属）。
- **操作列**（固定右列，宽度 260）：
  - 「查看轨迹」link（和展开按钮等价）。
  - 「查看业务单」link。
  - 「更新轨迹」link（手动触发 API 拉最新一次，用于滞留但仍在途的运单——避免每 15 分钟等太久）。
  - 「标记已处理」link（仅异常状态显示——客服处理完异常后手动点，移除看板红卡计数）。
  - 「加入关注」开关（灰色/金色星标 toggle）。

#### 轨迹展开行（点击展开后）
内嵌 `el-timeline` 时间线组件，**最新轨迹在顶部**（倒序）：
- 时间戳（YYYY-MM-DD HH:mm:ss）。
- 节点状态文案（API 原文，如「快件已到达【深圳集散中心】」）。
- 所在城市（彩色小标签）。
- 异常节点有红色图标 + 加粗异常描述。

底部分页：`el-pagination`（10/20/50/100 条每页，defaultPageSize=20）。

### 7.3 操作步骤

#### 标准筛选流程
1. 左侧筛选栏设置条件（如：客户=某客户；快递商=顺丰；状态=运输中；日期=本月）。
2. 点击「查询」。
3. 若条件设置错误 → 点「重置」清空 → 重新设置。

#### 跳转业务单据
1. 在「关联业务」列，点击蓝色链接（如「销售发货单 SH-20260827-0003」）。
2. 系统新开标签页跳转到 03-销售管理模块的销售发货单详情页，可查完整出库信息、客户信息、关联销售订单。

#### 展开 / 查看轨迹
1. 点击最左侧 **▼** 展开按钮 → 行内展开 `el-timeline` 时间线。
2. 顶部为最新一条轨迹（倒序）。
3. 找异常点（红色图标+加粗），复制文字到快递客诉。
4. 若需要全部轨迹导出给客户，可点本列的「复制轨迹」按钮（展开后的右上）。

#### 手动更新轨迹（单条）
1. 运单已超过 24h 没新节点 → 点「更新轨迹」link。
2. 系统立即调用快递 API 拉最新 1 次。
3. 若拉到了新节点：ElMessage 「轨迹已更新，新增 2 条」；列表中「最新轨迹时间」列值会刷新。
4. 若拉不到新节点：提示「暂无新轨迹」（=快递那边实际没动）。

#### 标记异常已处理
1. 客服跟进完异常（如：已联系客户说明延误原因 / 已让快递重派 / 已退款）后，点击「标记已处理」link。
2. 弹窗二次确认：「确认该异常已处理？标记后异常卡片计数会减去 1 条，状态标签会加『已处理』徽标」。
3. 确认 → 状态标签从红「异常」变成红底+黄色的「异常·已处理」；顶部 KPI 红卡的「异常数」减 1；异常占比自动重算。
4. 可取消标记（同一按钮文字变为「取消已处理」）。

#### 加入关注（长期跟踪重要运单）
1. 客户催件的运单 → 点操作列的灰色「☆ 加入关注」图标。
2. 图标变为金色「★」。下次筛选时可按「关注」过滤（筛选栏底部有「仅看我的关注」开关，默认关）。
3. 再次点击金色★取消关注。

#### 批量操作
1. 表格首列勾选多条运单（全选 / 页内全选 / 逐条点）。
2. 顶部出现批量工具栏（选中 N 条）：
   - 批量导出 Excel。
   - 批量标记已处理（针对异常）。
   - 批量加入/取消关注。
3. 点击对应批量按钮，按提示操作。

#### 导出 Excel
1. **按筛选导出**：设置筛选条件后点右上「导出筛选结果」→ 下载 `运单列表_筛选结果_YYYYMMDD_HHmm.xlsx`。
2. **全部导出**：点「导出全部」→ 下载 `运单列表_全部_YYYYMMDD.xlsx`（权限：销售只能导出自己的，仓库/客服/管理员导出全量）。
3. Excel 内容与列表列一致，末尾加一列「完整轨迹（拼接文本）」便于直接发客户。

### 7.4 注意事项

- **角色过滤默认生效**：业务员打开列表，看不到其他业务员负责客户的运单；因此「导出全部」对销售来说 = 全部自己的运单（不是真的公司全部）。需要全量的，请找仓库管理员或管理员账号。
- **分页与全选**：顶部全选 = 当前页全选，不是所有页。若需批量处理 1000 条以上运单（如月度全量导出），建议先用筛选条件分批。
- **轨迹更新频率**：系统默认每 15 分钟后台自动拉一次在途运单的轨迹。手动点「更新轨迹」= 立即补拉一次，不计入后台频率（不节流）。
- **轨迹接口失败**：若 4 次以上 API 返回失败（网络抖动或快递商接口限流），会在「异常类型」打 EX-07 自定义码（接口失败），管理员可在系统参数中开启「顺丰/京东备用接口」切换。
- **复制运单号到剪贴板**：页面需 HTTPS 或本地 localhost 才能使用系统剪贴板 API；若是普通 HTTP 环境，复制会失败，会降级为 alert 提示文本让用户手动复制。
- **标记已处理≠异常解除**：标记已处理只是告诉看板「这个异常我已经在处理」，不是让系统把状态从 exception 改成正常。若快递商实际返回正常轨迹，状态会在下一次 API 拉取时自动变回 picked / delivering / signed。

## 8. 异常追踪与状态详情

### 8.1 功能说明

本章将 6 类标准异常的处理 SOP 单独汇总成「客服日常 15 分钟运维脚本」。

### 8.2 操作步骤（6 类异常分别处理）

#### EX-01 超期未签收
1. 看板 → 点击 KPI「异常数」红卡 → 跳到列表自动筛 EX-01。
2. 展开每条运单的轨迹，看最后一条轨迹节点：
   - 若已「派送中」→ 直接联系客户询问是否收到（若已收到，点「手动标记已签收」——需管理员权限，标记后状态变 signed，原轨迹保留）。
   - 若仍在「运输中」超过预计到达日 → 联系快递客服查询为什么滞留（天气/爆仓/疫情等）。
3. 跟进完成 → 点击「标记已处理」。

#### EX-02 签收失败 / 拒收
1. 列表中筛选 EX-02，查看轨迹文案：
   - 「客户拒收」→ 通知销售联系客户，问原因（错发/质量/不需要）→ 决定重发/做退货处理（进入销售退货流程）。
   - 「无人接听 / 地址不详」→ 联系客户确认地址/电话后，通知快递二次派送。
2. 确认处理方案 → 标记已处理。

#### EX-03 轨迹滞留超时（>24h 无新节点）
1. 点「更新轨迹」先手动拉一次 → 若有新节点：自解。
2. 若仍无 → 联系快递客服（报运单号）问原因，通常是分爆仓、天气、安检问题。
3. 告知客户大致预期到达时间 → 标记已处理。

#### EX-04 安检/清关异常
1. 海关扣关 → 联系报关同事处理（补缴税款/补资料）；若是国内安检 → 联系快递查明是否有禁运品（锂电池/液体），按要求补发票或退回重发。
2. 记录处理结论 → 标记已处理。

#### EX-05 揽收失败（>48h 无揽收）
1. 查销售发货单：仓库是否真的发货？
   - 仓库没发货：通知仓库安排发货。
   - 仓库已发货但快递没来拿：联系快递员催件。
2. 若发现单号输入错误（错号），在销售发货单中更正为正确单号，重新发货 → 本运单在列表中自动消失，新单号进入列表。

#### EX-06 发货后无轨迹（>24h）
1. 复制单号 → 在快递官网官网直接查询。
   - 官网也查不到 → 99% 是单号填错。联系仓库核对原始面单并在 ERP 中改单号。
   - 官网能查到 → 说明第三方对接接口有问题 → 联系运维切换备用接口或联系快递 100 客服。
2. 修复后点「更新轨迹」→ 新轨迹出现。

### 8.3 注意事项

- 每类异常建议设置「处理时限」系统参数（默认 2h 内客服首次响应，24h 内处理完毕），处理超时会自动在工作台给客服负责人推「超期异常工单」。
- 所有跟进沟通记录建议同步到对应业务单据（销售发货单/采购到货单）的「操作备注」栏或 CRM 跟进记录，便于后续追溯。

## 10. 附录：常见问题

### Q1：为什么运单显示「已发货」但列表中找不到？
A：可能原因（3 点按顺序排查）：
1. 销售发货单中「快递单号」栏为空 → 列表不会显示（物流监控模块依赖单号）。补填单号后系统下一轮同步时出现（最长 15 分钟）。
2. 销售发货单的「发货日期」超出当前筛选的日期范围 → 在左侧筛选区把日期范围放宽（如选「近 30 天」或手动选）。
3. 当前角色权限看不到（如销售 A 开单但销售 B 登录 → 查不到）。用仓库管理员账号验证。

### Q2：运单明明客户已实际签收，但看板还显示「派送中」？
A：典型的 API 轨迹未同步。3 种处理方式（任选其一）：
1. 点操作列「更新轨迹」手动拉一次，若 API 返回了签收信息立即变更。
2. 手动拉还没变更 → 等下一轮后台自动同步（≤ 15 分钟）。
3. 15 分钟后仍不变 → 说明快递 API 确实还没返回签收（快递系统延迟），在客户确认签收的情况下请管理员点击「手动标记已签收」（列表中「更多操作」菜单）。

### Q3：OTHER 类型的快递怎么没有轨迹？
A：OTHER（专线/同城配送）默认没有标准 API 对接。轨迹靠 2 种方式维护：
1. 仓库/客服在运单详情页手动录入最新节点（菜单：「更多→手动添加轨迹」）。
2. 管理员配置「专线物流 Webhook」——专线方给我方推送轨迹，自动写入列表。
若以上都没配置，OTHER 类型运单的状态只有「待揽收→派送中→已签收」三步，靠仓库在发货/确认签收时手动切换。

### Q4：销售发货单改了单号，为什么老单号还在列表？
A：老单号（原绑定的运单记录）不会自动删，状态变成「作废」标签（灰色、不计数），筛选「全部」也能看到（用于审计追溯）。若确定不需要了可由管理员手动删除作废记录。

### Q5：「在途总金额」和财务应收账款对不上？
A：5 个常见差异点：
1. 口径：物流在途 = 已发货未签收（不管开票）；财务应收 = 已开票且未回款（不管是否签收）。
2. 币种/汇率换算差异。
3. 销售发货单是未税，财务应收是含税 → 差 13% 增值税。
4. 部分运单是赠品（无金额）/免费补发（金额=0），物流仍算在运但财务不计应收。
5. 退货/退款未同步在物流和财务两边同时更新。
> 如需对账，请以财务模块为准，物流看板金额仅做业务规模参考。

### Q6：客户要求把轨迹原文发邮件怎么办？
A：3 种方式任选：
1. 单条运单 → 展开轨迹 → 右上「复制轨迹」→ 粘贴到邮件正文。
2. 多条运单（同客户）→ 勾选这些运单 → 批量操作栏的「批量复制轨迹文本」。
3. 导出筛选结果 Excel → Excel 最后一列含完整轨迹，直接发文件。

### Q7：接口限流导致很多运单拿不到轨迹？
A：快递 100 等接口按账号有日请求次数上限。临时处理：
1. 管理员在系统参数中把「同步频率」从 15 分钟调到 30 分钟/1 小时（暂时）。
2. 联系快递 100 升级账号（买更高额度）。
3. 大客户可直接接入顺丰 BSP / 京东 VOP 等官方直连（不限流），请咨询实施顾问。

### Q8：「标记已处理」后异常数没减？
A：通常是浏览器缓存，按 F5 刷新整个页面。若刷新仍不对：
1. 请确认当前账号是否有该运单的权限（如销售标记了不属于自己的运单）。
2. 该运单状态是否已在最近一次 API 同步中实际解除异常 → 那么异常数本来就不该算它了，减两次反而错，前端可能有缓存。
